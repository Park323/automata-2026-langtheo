# 파일럿 문장 세트 v0

`docs/spec.md` 12.2의 ①②③에 쓰는 문장 10개입니다.
전부 **요격기 분담 협상** 상황이라 시뮬레이션 프롬프트와 결이 같습니다.

## 설계 원칙

- 각 문장이 **자질 하나를 주로** 시험하되, 문장 자체는 자연스러울 것
- 3개 언어로 **같은 내용**을 쓸 것 (③ 길이 상한 측정용)
- 숫자를 포함한 문장을 둘 것 (지표 6a 대조 검증용)
- **어느 방향에서 무엇이 생기고 사라지는지 예측을 미리 적을 것** — 예측이 빗나가면
  그것이 곧 발견입니다

## 검사할 자질 4개

| 자질 | 무엇을 보는가 |
|---|---|
| `condition` | 조건절이 살아남는가 → **조건부 동의가 확약으로 변하는가** |
| `hedge` | 유보·추정이 살아남는가 → **추정이 사실로 굳는가** |
| `tense` | 시제·상이 살아남는가 → **약속과 사실이 섞이는가** |
| `subject` | 주체가 명시되는가 → **책임 소재가 생기거나 사라지는가** |

> 12.7 0순위로 감축할 때는 `condition`과 `subject` 둘만 남깁니다.
> 앞엣것이 연쇄에 가장 직결되고, 뒤엣것이 **생성률**의 주력이기 때문입니다.

## S1 — 조건부 확약

| | |
|---|---|
| ja | 他の二国が先に確約すれば、30を出します。 |
| zh | 如果另外两国先承诺，我们也出30。 |
| fr | Si les deux autres pays s'engagent d'abord, nous verserons 30 également. |

`condition` · `tense` · `subject` · 숫자

**예측** — `ja→fr`: 주어 생성(`nous`). `ja→zh`: 미래시제 소실.
조건절이 깎이면 **"조건부 동의"가 "확약"으로** 뒤집힙니다. 가장 위험한 실패 유형.

## S2 — 완곡 거절 ★

| | |
|---|---|
| ja | 検討させていただきます。 |
| zh | 我们会研究一下。 |
| fr | Nous allons l'examiner. |

`hedge`

**예측** — 일본어에서는 사실상 **거절**인데, `fr`/`zh`로 가면 **긍정적 검토**로 읽힙니다.
관용을 아는 것과 단어를 옮기는 것의 차이라 번역기가 잡기 가장 어렵습니다.

> **이 문장 하나가 파일럿의 핵심입니다.** 여기서 뒤집힘이 관측되면 장치가 살아 있습니다.

## S3 — 헤지 + 추정 수치

| | |
|---|---|
| ja | 確かではありませんが、進捗は半分ほどかと思われます。 |
| zh | 不太确定，进展大概一半左右。 |
| fr | Je n'en suis pas certain, mais l'avancement serait d'environ la moitié. |

`hedge` · `subject`

**예측** — `fr`의 조건법 `serait`가 `ja`/`zh`에서 단정으로 바뀌면 **추정이 사실**이 됩니다.

## S4 — 주어 생략 ★생성률 주력

| | |
|---|---|
| ja | 用地を決められませんでした。 |
| zh | 用地还没定下来。 |
| fr | Nous n'avons pas pu choisir le site. |

`subject` · `tense`

**예측** — `ja→fr`, `zh→fr`에서 **주어가 반드시 생성**됩니다(`fr`이 주어를 문법적으로 강제).
누가 못 정했는지가 원문엔 없는데 번역문엔 생깁니다 — **책임 소재의 생성.**

> 이 방향은 구조적으로 100%에 가깝게 나와야 합니다. **사전이 작동하는지 검증하는
> 양성 대조**이기도 합니다. 여기서 안 잡히면 `subject` 표지 목록이 잘못된 것입니다.

## S5 — 시제 모호 ★zh 특유

| | |
|---|---|
| ja | 我々は迎撃機に投資しました。 |
| zh | 我们投资拦截器。 |
| fr | Nous avons investi dans l'intercepteur. |

`tense`

**예측** — `zh`는 시제 표지가 없어 "낸다/냈다"가 구분되지 않습니다.
`zh→ja`, `zh→fr`에서 **시제가 생성**되며, 번역기가 어느 쪽을 고르는지가 관측 대상입니다.
**약속이 사실로 굳으면** 상대가 안심하고 분담을 줄입니다.

## S6 — 조건법 ★fr 특유

> **조건법(mood)은 조건절(clause)이 아닙니다.** `pourrions`·`かもしれ`·`可能` 은
> `hedge` 로 셉니다. 조건 연결사(`si`/`ば`/`如果`)가 없으므로 `condition` 은 0 이 맞습니다 —
> 역접(`mais`/`が`/`但`)을 `condition` 에 넣으면 극히 흔한 단어라 지표가 무의미해집니다.

| | |
|---|---|
| ja | 出せるかもしれませんが、予算が厳しいです。 |
| zh | 我们可能出，但预算紧张。 |
| fr | Nous pourrions verser, mais le budget est serré. |

`hedge` · `condition`

**예측** — `fr`의 조건법 `pourrions`가 `ja`에서는 `かもしれません`으로 대응 가능합니다.
**보존되면** "정교하게 말한 쪽이 손해 보지 않는다"는 뜻이고,
**깎이면** 2.1의 *"정교하게 말한 쪽이 더 크게 오해받는다"*가 확인됩니다.

## S7 — 수치 다중 (대조군)

| | |
|---|---|
| ja | 閾値は120、現在は45です。残りは75です。 |
| zh | 阈值是120，现在45。还差75。 |
| fr | Le seuil est de 120, actuellement 45. Il reste 75. |

숫자만

**예측** — **세 숫자가 전부 그대로 도착해야 합니다.**
여기서 숫자가 변하면 지표 6a가 대조군 역할을 못 하므로, **번역 모델을 바꿔야 하는 신호**입니다.

## S8 — 단복수 ★zh 특유

| | |
|---|---|
| ja | 国が反対しています。 |
| zh | 国家反对。 |
| fr | Les pays s'opposent. |

`subject`

**예측** — `zh`는 복수 표지가 없어 한 나라인지 여러 나라인지 불명확합니다.
`zh→fr`에서 **수가 생성**됩니다. 한 나라의 반대가 여러 나라의 반대로 커질 수 있습니다.

## S9 — 조건 + 부정

| | |
|---|---|
| ja | 先に出さないのであれば、こちらも出しません。 |
| zh | 如果你们不先出，我们也不出。 |
| fr | Si vous ne versez pas d'abord, nous ne verserons pas non plus. |

`condition` · `subject`

**예측** — 이중 부정 구조가 깎이면 **위협이 사라지거나 반대로 강해집니다.**
조건절 소실의 결과가 S1과 반대 방향이라 짝으로 봅니다.

## S10 — 긴 복합문 (길이 측정 주력)

| | |
|---|---|
| ja | 我が国の用地はまだ用途が決まっておらず、シェルターにするか迎撃機にするかで国内の意見が分かれています。ただ、他国が迎撃機を引き受けてくれるのであれば、こちらはシェルターに傾くと思います。 |
| zh | 我国的用地还没决定用途，国内对于建避难所还是建拦截器意见分歧。不过，如果别的国家愿意承担拦截器，我们可能会倾向于避难所。 |
| fr | L'usage de notre terrain n'est pas encore décidé, et les avis divergent dans le pays entre l'abri et l'intercepteur. Cependant, si un autre pays prenait en charge l'intercepteur, nous pencherions plutôt pour l'abri. |

`condition` · `hedge` · `subject` · `tense` 전부

**예측** — 실제 협상 발화에 가장 가까운 길이와 복잡도입니다.
**③ 길이 상한 측정의 주력**이며, 여기서 언어별 글자 수 비율을 뽑습니다.

## 사전 자체 검증 — 이미 한 번 돌려봤습니다

`domains/meteor/lexicon/markers.yaml`을 위 문장에 적용한 결과입니다.

| 문장 | 자질 | ja | zh | fr | 판정 |
|---|---|---:|---:|---:|---|
| S1 | `condition` | 1 | 1 | 1 | 전 언어 검출 ✓ |
| S1 | `tense` | 1 | **0** | 1 | **zh의 시제 부재가 잡힘** ✓ |
| **S4** | **`subject`** | **0** | **0** | **1** | **★ 생성 검출. 양성 대조 통과** |
| S6 | `hedge` | 1 | 1 | 1 | fr 조건법 `pourrions` 정규식 ✓ |

**S4가 핵심입니다.** `ja`/`zh`에 주어가 없고 `fr`에만 있으므로,
`ja→fr` 번역에서 주어가 생기면 **생성률이 정확히 잡힙니다.**

### 이 검증에서 버그 두 개를 잡았습니다

| 버그 | 증상 | 수정 |
|---|---|---|
| **이중 계수** | `我们`이 `我`에도 걸려 `subject`가 2로 셈 | `match: longest_first` 규칙 추가. 긴 표지부터 매칭하고 겹친 구간은 소비 |
| **과거 부정형 누락** | `決められませんでした`가 `ました`에 안 걸려 `tense`가 0 | `ませんでした` / `でした` 패턴 추가 |

수정 후 `S1 zh subject`는 2 → **1**, `S4 ja tense`는 0 → **2**로 정상화됐습니다.

> **문장을 먼저 짜고 사전을 역산한 덕에 이 버그들이 지금 잡혔습니다.**
> 사전부터 만들었다면 파일럿 결과가 나온 뒤에야 발견했을 것이고,
> 그때는 "번역이 안 깎였다"인지 "사전이 못 센다"인지 구분할 수 없었을 것입니다.

## 실행 방법

### ① 왕복 손실

```
6방향 : ja→zh  ja→fr  zh→ja  zh→fr  fr→ja  fr→zh
각 방향에 S1~S10 → 사전 카운터로 소실률·생성률 산출
```

**눈으로 판정하지 않습니다.** `domains/meteor/lexicon/markers.yaml`로 셉니다.

| 결과 | 조치 |
|---|---|
| 자질별로 갈림 (숫자 높고 조건절 낮음) | **정상.** 진행 |
| 형체를 알 수 없게 망가짐 | 번역 모델을 더 큰 것으로 |
| 거의 온전히 보존 | 장치 고장. 모델을 작게, 최후엔 pivot 재도입 |
| **S4에서 `subject` 생성이 안 잡힘** | **사전 오류.** 표지 목록부터 고칠 것 |

### ② 지시별 차이

S1·S2·S6·S10 (자질이 많은 것들)에 대해:

```
translate_instruction = null            → "번역하라" 만
                      = "정확하게 옮겨라"
                      = "간결하게 하라"
```

세 줄에 차이가 없으면 `translate_instruction`을 스펙에서 되돌립니다.

### ③ 언어별 길이 상한

#### 위 10문장으로 이미 재봤습니다 (v0 추정치)

| | ja | zh | fr |
|---|---:|---:|---:|
| 10문장 합계 (자) | 256 | 163 | **636** |
| S10 단독 (자) | 93 | 60 | **215** |
| **비율 (fr=100)** | **43** | **28** | **100** |

`fr`은 같은 내용에 **`ja`의 약 2.5배, `zh`의 약 3.9배** 글자를 씁니다.

> **100자 균일 상한을 걸었다면 `fr`은 `zh`가 하는 말의 28%밖에 못 했을 것입니다.**
> 그리고 결과가 나온 뒤 *"C국이 조율에 실패한 것이 번역 때문인가 글자 수 때문인가"*를
> 구분할 방법이 없었을 것입니다.

#### 설정 방법

**`fr` 상한을 먼저 정하고 나머지를 비례 배분합니다.** `fr`이 제약이기 때문입니다.

```yaml
length:
  message_max_chars:
    fr: 200        # 먼저 정함
    ja: 86         # 200 × 0.43
    zh: 56         # 200 × 0.28
```

#### 파일럿에서 다시 잴 것

위 수치는 **저자 1인이 옮긴 10문장** 기준이라 표본이 작습니다. 파일럿에서:

- 문장 수를 늘리거나 다른 사람이 옮긴 판본과 대조
- **왕복 번역 결과물의 길이**도 함께 측정 — 번역기가 언어별로 얼마나 늘리고 줄이는지
- 초과율이 언어별로 크게 다르면 비율이 틀린 것 (`docs/spec.md` 5.3)

**측정값과 산출 근거를 `RESULTS.md`에 남기세요.**
*"fr이 글자 수가 모자라서 진 것 아니냐"*는 반박을 막는 유일한 방법입니다.

> **부수 효과:** `fr` 메시지가 길어 번역 토큰도 많이 듭니다.
> 12.4 호출량 산정 시 국가별 편차를 감안하세요.

### ④ 목표 지향성

문장이 아니라 **에이전트 5턴**을 돌려 `reasoning`을 읽습니다.
목적함수를 주지 않으므로, 일관되게 움직이는지만 확인합니다.
