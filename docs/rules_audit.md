### 정합 검토에서 함께 나온 코드 버그 둘

**B1 — 병렬 경로에서 유언·선물·採決 결과가 조용히 사라진다.**
`_notify(..., world.turn, ...)` 로 넣는 세 사건(`testament` [loop.py:298](../core/loop.py#L298),
`gift` [loop.py:539](../core/loop.py#L539), `ballot_result` [loop.py:644](../core/loop.py#L644))은
**그 턴의 큐 수거가 끝난 뒤에** 들어갑니다. 병렬 경로의 `_dequeue_inbox` 는
`deliver_turn == world.turn` **만** 가져가고 그 직후 `deliver_turn > world.turn` 이 아닌 것을
전부 버리므로([loop.py:438,732](../core/loop.py#L438)), 다음 해에는 아무도 받지 못합니다.

```
큐: [(5, 'Asla1'), (5, 'Asla1')]
병렬: 턴6 에 받은 것 []        ← 유언도 선물도 사라졌다
순차: 턴6 에 받은 것 [{'testament': ['남긴 말']}]
```

순차 라운드로빈은 `deliver_turn <= world.turn` 이라 무사합니다
([loop.py:877](../core/loop.py#L877)). `inh30` 은 순차였으므로 그 런의 관측은 영향받지
않습니다 — 다만 **병렬로 돌린 런의 유언·선물·採決 통지는 전부 무효**입니다.

**B2 — `can_act` 가 항상 참이다.**
마지막 줄이 `_afford(ap, min(cfg.ap.memory_write, cfg.ap.vote))`
([agent_loop.py:768](../core/agent_loop.py#L768))인데 `ap.memory_write = 0.0` 이라
**AP 가 0 이어도 참**입니다. 게다가 `memory_write` 는 압박선 아래에서 도구 목록에 없는데
그 값을 「공짜 행동」 으로 세고 있습니다.

```
    AP    예산  memory_open  can_act   실제로 부를 수 있는 것
   0.0   1000        False     True   — 없음 —
  0.04   1000        False     True   — 없음 —
```

결과: 종료 조건 ②(자원 소진)가 죽었고, 라운드로빈은 AP 0 인 사람을 한 번 더 깨워
`end_turn` 만 시킵니다 — 에이전트-해마다 API 호출 하나가 그렇게 나갑니다.

### 노브 — 핵심 독립변수가 예산 240 위에서 죽는다

```
한 해 AP 1.0 · speak 0.2  →  국제 발신은 한 해 **최대 5건**

  노브 6    5건 전액   30      노브 24   120
  노브 12              60      노브 48   240
```

예산이 `5 × 노브` 이상이면 **말할 수 있는 횟수를 정하는 것은 AP 뿐**이고, 노브 6 과 48 의
행동 집합이 완전히 같아집니다. 남는 차이는 잔액 210원인데, 5건을 말한 시점에 AP 가 0 이라
**그 해에는 그 돈을 쓸 손이 없습니다.** 다음 해 예산에 쌓일 뿐입니다.

`inh30` 실측 예산은 **중앙 588 · 최대 2,987** 입니다 — 중앙값이 이미 240 의 2.4배입니다.

노브가 무는 경로는 둘만 남습니다.

```
① 예산 < 240 인 해 (젊거나 크게 쓴 뒤)
② 말하기와 투자를 **섞을** 때의 상대가격 — (speak, invest) 조합별 최소 예산

   조합       (0,5) (1,4) (2,3) (3,2) (4,1) (5,0)
   노브  6      200   166   132    98    64    30
   노브 48      200   208   216   224   232   240
```

②가 실질입니다. 예컨대 예산 100원이면 노브 6 은 「3번 말하고 2번 투자」 가 되지만
노브 48 은 「2번 말하기」 가 한계입니다. 그러나 **예산 240 을 넘는 순간 두 표가 같아집니다.**

> `Δx = x̂(48) − x̂(6)` 이 예산 하위 구간의 에이전트-해에서만 나온다면, 지금 격자는
> 노브가 아니라 **가난**을 재고 있을 위험이 있습니다. 조건별 표를 낼 때 예산으로 층화하고,
> 예산 < 240 인 에이전트-해의 비율을 같이 보고해야 합니다.

### ★A 와 ★B 가 같은 값인 것은 우연이 아니다

`A = 3 × epoch × per_country` · `B = total × per_country` 이고 지금 `3 × 20 = 60` 이므로
두 조건이 **정확히 같은 수**가 됩니다 (9,569). 창의 하한을 정하는 것은 사실상 ★E 하나뿐이고,
★A 는 지금 아무것도 안 거릅니다. `epoch_turns` 를 건드리면 그때 갈립니다.
`epoch_turns: 20` 의 주석은 「기대수명 반올림」 이라고 적혀 있는데 기대수명은 16.06 입니다
([base.yaml:245](../configs/base.yaml#L245)).
