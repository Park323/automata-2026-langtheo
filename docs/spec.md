# 구현 스펙 — langtheo

> 기획은 `worksheet.md`에 있습니다. 이 문서는 **그것을 코드로 옮기기 위한 명세**입니다.
> 구체적인 숫자는 여기 없습니다. 전부 `config.yaml`로 갑니다 (7장).
>
> **미결 사항은 12장에 모아뒀습니다.** 구현 전에 그것부터 확인하세요.

## 1. 설계 원칙 (불변)

이걸 어기면 결과가 설정의 귀결이 되어 실험이 죽습니다. 코드 리뷰의 첫 번째 기준입니다.

1. **자연어를 끝까지 유지한다.** 에이전트 간 메시지는 구조화 필드가 아니라 자유 텍스트다. 손실을 필드 드롭으로 흉내내지 않는다
2. **왜곡을 주입하지 않는다.** 번역 호출에 "왜곡하라", "정보를 빠뜨려라"를 쓰지 않는다. `"번역하고 간결하게 정리하라"`만 시키고, 무엇이 얼마나 깎이는지는 **관측 대상**이다
3. **프롬프트에 평가어와 지시를 넣지 않는다.** "위험", "부족", "협력해야 한다" 금지. 정량 정보와 사실만
4. **행동 제약은 세계가 건다.** 프롬프트로 아끼라고 말하지 않고, 쓰면 없어지게 만든다
5. **에이전트는 전역 상태에 접근하지 않는다.** 자기 관측 + 받은 메시지만
6. **모든 상수는 config에 있다.** 코드에 숫자 리터럴을 박지 않는다

## 2. 세계 구조

### 2.1 국가 · 에이전트 · 언어

```
국가 3개 : C_A, C_B, C_C
각 국가에 에이전트 3명 → 세대당 9명
```

**각 국가는 서로 다른 실제 자연어를 모국어로 씁니다.** (예: ko / ja / en)

에이전트는 자기 모국어로 발화하고, 자기 모국어로 된 것만 원문 그대로 읽습니다.
번역 손실을 흉내낼 필요가 없습니다 — **진짜 번역이므로 진짜로 손실됩니다.**

각 에이전트의 상태:

| 필드 | 설명 |
|---|---|
| `id` | `A1`, `A2`, `B1` … |
| `country` | 소속 국가 |
| `native_lang` | 모국어 |
| `known_langs` | 읽을 수 있는 언어 집합. 초기값은 모국어만 |
| `budget` | 이번 턴에 쓸 수 있는 예산 |
| `happiness` | 누적 사적 재화 |
| `alive` | 생존 여부 |

**개체차는 두지 않습니다.** 전원 동일한 프롬프트 골격, 동일한 초기값입니다.
(동일한데도 분화가 일어나는지가 관측 대상)

### 2.2 시간

```
1 세대 = lifespan 턴
전체   = generations × lifespan 턴
재앙   = 전체 마지막 턴에 도달
```

**에이전트는 재앙까지 남은 시간을 모릅니다.** 매 세대가 "우리 대에 올 수도 있다"는
불확실성 아래 삽니다. 대부분의 세대는 실제로는 재앙을 겪지 않습니다.

> 주최측 페이퍼 시좌 ⑥ **時間軸の安全保障**(현세대 최적화 × 미래세대 안전)에 해당합니다.
> README에 명시할 것.

### 2.3 국토와 시설

각 국가는 **국토 1칸**을 가집니다.

```
land[country] ∈ { null, "bunker", "interceptor" }
```

- 두 시설은 **공존할 수 없습니다**
- `null` 상태에서 시설 투자가 처음 들어오면 **그 용도로 확정**되고, 이후 변경 불가
- 확정 전에 국내 다수결로 용도를 미리 정할 수 있습니다 (선택 — 4.3 참조)

즉 **먼저 투자한 사람이 국가의 운명을 정합니다.** 이걸 막고 싶으면 다수결을 써야 하고,
다수결은 비용과 턴을 씁니다. 쓸지 말지는 에이전트가 결정합니다.

### 2.4 시설 진척

```
progress[country] : 해당 국토 시설의 누적 진척도
interceptor_total : 전 국가 요격기 진척의 합
```

투자는 **확률적으로만** 진척이 됩니다.

```
증가분 = Binomial(n = 투자량, p = success_prob)
```

`success_prob`은 **고정 상수이며 에이전트에게 공개되지 않습니다.**
에이전트는 자기 투자량과 자국의 관측된 진척만 봅니다. 타국 진척은 소통으로만 압니다.

### 2.5 생존 판정 (마지막 턴)

```
if interceptor_total ≥ threshold_interceptor:
    전원 생존
else:
    progress[c] ≥ threshold_bunker 이고 land[c] == "bunker" 인 국가의 국민만 생존
    나머지 사망
```

**요격기 유치국은 벙커가 없으므로, 요격 실패 시 전원 사망합니다.**

## 3. 실행 루프

### 3.1 턴 처리 순서

```
1. 관측 스냅샷    전 에이전트의 관측을 동시에 고정
2. 병렬 추론      전원이 각자 LLM 호출 (서로의 이번 턴 행동을 모름)
3. 검증           예산 초과·불가능한 행동 거부
4. 환경 갱신      투자 집계 → 확률 판정 → 진척 반영, 국토 확정
5. 메시지 큐잉    이번 턴에 보낸 메시지는 다음 턴에 도착
6. 로그 기록
```

**메시지가 다음 턴에 도착한다는 점이 중요합니다.** 되묻기가 실제로 턴을 소비해야
"확실해지지만 시간을 쓴다"는 딜레마가 성립합니다.

### 3.2 세대 전환

`lifespan` 턴마다:

| 항목 | 처리 |
|---|---|
| 에이전트 | 전원 사망, 신규 9명 생성 |
| 예산 | 초기화 |
| `happiness` | 소멸 (사적 재화는 대물림되지 않음) |
| 국토·진척 | **유지** |
| 언어 능력 | 소멸. 단 계승 조건 적용 (4.3) |

## 4. 에이전트

### 4.1 관측 — 프롬프트에 들어가는 것

**정량 정보와 사실만.** 평가어 금지.

```
당신: A1 (국가 A)
읽을 수 있는 언어: ko
예산: 20
행복: 3

자국 국토: 미정
자국 진척: 0
자국의 언어 학습자 수: 0

이번 턴 도착한 메시지:
  [1] B2로부터 [AI 번역]
      "..."
  [2] A3로부터
      "..."
```

**절대 넣지 않는 것**

- 재앙까지 남은 턴
- `success_prob`
- 타국의 진척·예산·국토 (메시지로만 알 수 있음)
- 다른 에이전트의 내심
- 원문과 번역문의 차이

### 4.2 응답 스키마

```json
{
  "reasoning": "왜 이렇게 했는지 한 문장",

  "spend": {
    "happiness": 0,
    "facility":  0,
    "learn":     null
  },

  "message": {
    "to":     "B2",
    "kind":   "say",
    "text":   "자연어 본문 (모국어)",
    "intent": "내가 전하려 한 것 한 문장"
  },

  "received": [
    { "msg_id": 1, "understood": "무슨 뜻으로 이해했는지 한 문장" }
  ],

  "propose_vote": null
}
```

| 필드 | 설명 |
|---|---|
| `reasoning` | **필수.** 사후 분류의 감사 표면 |
| `spend.facility` | 자국 국토 시설에 투자. 국토가 `null`이면 이 투자가 용도를 확정 |
| `spend.learn` | 배울 언어 코드 또는 `null` |
| `message.kind` | `"say"` 또는 `"ask"` (되묻기 — 비용이 다름) |
| `message.intent` | **채널을 타지 않습니다.** 로그에만 남아 채점에 쓰입니다 |
| `received[].understood` | 직전 턴에 받은 메시지를 어떻게 이해했는지. 채점용 |
| `propose_vote` | 국토 용도 다수결 발의 (`"bunker"` / `"interceptor"` / `null`) |

> `intent`와 `understood`는 **에이전트끼리 절대 볼 수 없습니다.** 로그 전용입니다.
> 이걸 프롬프트에 노출하면 왜곡이 즉시 드러나 실험이 죽습니다.

### 4.3 행동과 비용

| 행동 | 비용 키 | 비고 |
|---|---|---|
| 대기 | `turn_base` | 아무것도 안 해도 소모 |
| 자국 내 소통 | `comm_domestic` | 원문 직통 |
| 국제 소통 — 수신자 언어를 앎 | `comm_intl_learner` | 원문 직통 |
| 국제 소통 — 모름 | `comm_intl_ai` | **2단 번역.** ← 노브 |
| 되묻기 (`kind: "ask"`) | `ask_clarification` | 비용 + 다음 턴 소비 |
| 언어 학습 (신규) | `learn_new` | 일시불. 분할 불가 |
| 언어 학습 (계승) | `learn_inherit` | 아래 조건 충족 시 |
| 행복 구매 | `happiness_unit` | 사적 재화 |
| 시설 투자 | 자유 (턴당 상한) | 확률적으로 진척 |
| 다수결 발의 | `propose_vote` | 발의 턴에 자국민 투표, 과반으로 확정 |

**계승 조건**

```
직전 세대 자국에 해당 언어 학습자가 1명 이상 있었으면 → learn_inherit
없었으면                                              → learn_new
```

한 세대라도 끊기면 다시 전액입니다. **비가역성이 여기서 나옵니다.**

**국제 소통 경로 결정**

```
수신자가 발신자의 모국어를 안다  →  원문 직통
모르면                          →  2단 번역 + [AI 번역] 라벨
```

즉 **비용을 정하는 건 수신자의 언어 능력**입니다.

## 5. 소통

### 5.1 경로 3종

| 경로 | 전달 | 라벨 | 왜곡 |
|---|---|---|---|
| 자국 내 | 원문 | 없음 | 없음 |
| 국제 · 수신자가 앎 | 원문 | 없음 | 없음 |
| 국제 · 모름 | 2단 번역 | `[AI 번역]` | **발생** |

### 5.2 2단 번역

에이전트 호출과 **별개의 LLM 호출** 2회입니다.

```
1) L_발신자  →  pivot
2) pivot     →  L_수신자
```

두 호출 모두 지시는 **이것만**입니다:

```
번역하고 간결하게 정리하라.
```

**금지**

- ❌ "왜곡하라", "정보를 빠뜨려라", "유보 표현을 제거하라"
- ❌ 원문을 함께 전달하는 것
- ❌ 번역 품질에 대한 어떤 언급도 프롬프트에 넣는 것

무엇이 깎이는지는 우리가 정하지 않습니다. **"간결하게 정리하라"만 시켰을 때 무엇이
먼저 사라지는가**가 이 작품의 관측 대상입니다.

### 5.3 라벨

```
✅ [AI 번역]
❌ [AI 번역 — 부정확할 수 있음]
❌ [AI 번역 — 원문 대비 요약됨]
```

**채널 사실만.** 품질 언급은 평가어이자 정답 힌트라 창발을 죽입니다.

수신자는 경유 사실은 알지만 **무엇이 깎였는지는 모릅니다.** 그걸 알려면 원문을
읽어야 하고, 원문을 읽으려면 언어를 배웠어야 합니다.

### 5.4 되묻기

`kind: "ask"`는 비용 + **다음 턴 소비**입니다. 답이 도착할 때까지 한 턴을 잃습니다.

라벨이 있으므로 되묻기는 깜깜이 찍기가 아니라 **전략적 선택**이 됩니다.
제한된 검증 예산을 어디에 쓸지 고를 수 있으니까요.

## 6. 왜곡 관측

### 6.1 로그 스키마

`messages.jsonl` — 메시지 1건당 1행

```json
{
  "turn": 12,
  "msg_id": 47,
  "from": "A1", "to": "B2",
  "kind": "say",
  "route": "intl_ai",
  "src_lang": "ko", "dst_lang": "ja",

  "text_original":   "발신자가 쓴 원문",
  "text_pivot":      "1단 번역 결과",
  "text_delivered":  "수신자가 실제로 본 것",

  "intent":     "발신자가 기록한 의도 (채널 미경유)",
  "understood": "수신자가 기록한 이해 (다음 턴)",

  "numbers_original":  [30, 5],
  "numbers_delivered": [30, 5]
}
```

**세 텍스트를 전부 남기는 게 핵심입니다.** 어느 단계에서 무엇이 사라졌는지
사후에 추적할 수 있어야 합니다.

`numbers_*`는 정규식으로 추출한 수치 목록입니다. 지표 6(수치 왜곡률)에 씁니다.

### 6.2 사후 채점

별도 스크립트에서 오프라인으로 돌립니다. 시뮬레이션 중에는 하지 않습니다.

| 채점 | 방법 |
|---|---|
| 의도 전달 성공 | `intent` vs `understood`를 LLM 판정 (일치/불일치) |
| 수치 왜곡 | `numbers_original` vs `numbers_delivered` 집합 비교 (규칙 기반) |
| 무엇이 깎였나 | `text_original` vs `text_delivered`에서 조건절·유보·확신도 표현의 잔존 여부 분류 |

세 번째가 **가장 흥미로운 산출물**입니다. "무엇이 먼저 사라지는가"의 답이 여기서 나옵니다.

## 7. config 스키마

```yaml
knob:
  comm_intl_ai: 3          # 유일한 실험 변수

costs:
  turn_base:          ?
  comm_domestic:      ?
  comm_intl_learner:  ?
  ask_clarification:  ?
  learn_new:          ?
  learn_inherit:      ?
  happiness_unit:     ?
  propose_vote:       ?

thresholds:
  interceptor: ?
  bunker:      ?

budget:
  per_agent_per_turn: ?
  facility_cap_per_turn: ?

world:
  countries: [{id: A, lang: ko}, {id: B, lang: ja}, {id: C, lang: en}]
  agents_per_country: 3
  lifespan:    ?
  generations: ?
  success_prob: ?          # 에이전트 비공개
  pivot_lang: en

llm:
  agent_model:     ?
  translate_model: ?
  temperature:     ?

run:
  seed: ?
```

### 검증 — 로드 시 assert

```python
총자원 = budget.per_agent_per_turn * agents_per_country * lifespan

assert thresholds.interceptor > 총자원          # 혼자선 불가
assert thresholds.bunker      <= 총자원         # 우리끼리는 가능
assert 벙커_분담금 > 요격기_분담금               # 벙커가 더 비싸야 함

손익분기 = costs.learn_new / (knob.comm_intl_ai - costs.comm_intl_learner)
# 이 값이 lifespan보다 크면 그 조건에서는 학습이 산술적으로 불가능.
# 실패가 아니라 의도된 구간일 수 있으므로 assert 하지 말고 로그로 남길 것.
```

마지막 식을 매 실행 시 출력하세요. **노브 4단계가 교차점을 포위하는지 즉시 보입니다.**

| 4 | 의도 전달 실패율 | `intent` ≠ `understood` 비율 |
| 5 | 최종 진척도 | 마지막 턴 `interceptor_total` (연속값) |
| 6 | **수치 왜곡률** | `numbers_original` ≠ `numbers_delivered` 비율 ← **대조 지표** |

> **지표 6은 조건 간 차이가 없어야 성공입니다.**
> 지표 4와 짝을 이뤄 **"사실은 통과하고 의도만 깎인다"**를 입증합니다.
> 이게 없으면 "그냥 번역이 부실했던 거 아니냐"는 반박에 답할 수 없습니다.

**전제 점검:** 지표 4에 조건 간 차이가 아예 없으면 가설 반증이 아니라 **2단 번역 장치의
고장**입니다. 번역 경로부터 고쳐야 합니다.

## 10. 도메인 교체 구조

심사 3축 중 **프로덕트화**에 해당합니다. 디렉토리만 이렇게 잡으면 거의 공짜입니다.

core/         엔진. 도메인 개념 없음
              턴 루프 / 에이전트 기반 / 메시지 라우팅 / 번역 경로 / 로깅

  meteor/     운석. 국토·시설·생존 판정·프롬프트 템플릿

## 12. 미결 사항 — 구현 전에 확인할 것

### 12.1 세대 간에 무엇이 전달되는가 ← 가장 중요

현재 스펙은 **세계 상태만** 물려줍니다(국토·진척·계승 조건). 경험과 서사는 소멸합니다.

| 선택 | 결과 |
|---|---|
| **A. 아무것도 안 넘김** (현재 스펙) | "역사는 잊힌다"는 함의. 스코프 작음. 단 **겪고 배우는 경로가 없음** |
| **B. 직전 세대 결과 요약을 신세대 프롬프트에 붙임** | 실패를 겪고 학습으로 회귀하는 U자가 가능해짐. 프롬프트 한 블록 추가 |

**B가 없으면 "정성적 차이가 실리를 이긴다"는 결과가 나올 통로가 세대 안으로 제한됩니다.**
수명이 짧으므로 이건 실질적인 제약입니다. 결정 필요.

### 12.2 LLM 백엔드

로컬 Ollama(스윕 유리·설정 비용) vs API(품질·비용 병목). 지난 회차 상위작은 대부분 로컬
7B/14B였습니다. 번역 호출이 메시지마다 2회 추가되므로 총 호출량이 큽니다.

### 12.3 실제 언어 3종

`ko / ja / en`으로 갈지, 다른 조합으로 갈지. 7B급 모델의 언어별 능력차가 노이즈로 작용할
수 있으므로, 파일럿에서 **왕복 번역 후 조건절·유보가 살아남는지** 눈으로 확인해야 합니다.
형체를 알 수 없게 망가지면 pivot을 빼고 1단으로 줄입니다.

### 12.4 스텝 수

현재 워크시트는 `lifespan × generations = 100`. 권장은 30~60입니다.
1런 LLM 호출량이 크므로 (에이전트 호출 + 메시지당 번역 2회) **8/18 실측 후 확정**합니다.

### 12.5 지표 3의 조작적 정의

"의견을 바꿨다"를 `spend` 배분 방향 전환으로 잡았습니다. 이게 적절한지 확인 필요.
