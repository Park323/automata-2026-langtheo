## 1. 설계 원칙 (불변)

이걸 어기면 결과가 설정의 귀결이 되어 실험이 죽습니다. 코드 리뷰의 첫 번째 기준입니다.

1. **자연어를 끝까지 유지한다.** 에이전트 간 메시지는 구조화 필드가 아니라 자유 텍스트다. 손실을 필드 드롭으로 흉내내지 않는다
2. **왜곡을 주입하지 않는다.** 시스템은 번역 지시를 만들지 않는다. 지시는 발신 에이전트가 쓰고, 없으면 **아무 지시도 붙이지 않는다**(대상 언어만 사실로). 무엇이 얼마나 깎이는지는 **관측 대상**이다
3. **프롬프트에 평가어와 지시를 넣지 않는다.** "위험", "부족", "협력해야 한다" 금지. 정량 정보와 사실만. **목적함수도 주지 않는다** (4.1)
4. **행동 제약은 세계가 건다.** 프롬프트로 아끼라고 말하지 않고, 쓰면 없어지게 만든다
5. **에이전트는 전역 상태에 접근하지 않는다.** 자기 관측 + 받은 메시지만
6. **모든 상수는 config에 있다.** 코드에 숫자 리터럴을 박지 않는다

## 2. 세계 구조

### 2.1 국가 · 에이전트 · 언어

> **초기값이 전원 동일하지 않습니다** (8/17 개정).
>
> - **나이**를 `1..init_age_max`(10) 에서 뽑습니다. 전원 0살이면 **한꺼번에 죽습니다** —
>   20턴 실측에서 t14~19 에 9명이 전부 교체됐고, 그 6턴 사이에 쌓아둔 기억·관계·예산이
>   통째로 사라졌습니다. 세계가 주기적으로 백지가 되면 구전 감쇠를 관측할 수 없습니다.
> - **나라마다 한 명**이 이웃 나라 말을 이미 압니다 (순환: Asla→Ranoa→Miris→Asla).
>   그전에는 국내 구사자가 아무도 없어 학습이 **늘 정가 600** 이었고, 20턴 동안 학습
>   시도가 **0건**이었습니다. `x̂` 는 `L/2` 눈금이 존재해야 구간으로 좁혀집니다 (7장).
>
> `w*` 는 재확인했고 그대로입니다 (무성장 0.45 · 성장 0.20).

```
국가 3개 : C_A (ja) / C_B (zh) / C_C (fr)
각 국가에 에이전트 3명 → 상시 9명 (사망 시 즉시 충원)
번역은 언어 간 직역. 중계 언어(pivot)를 두지 않습니다.
```

**각 국가는 서로 다른 실제 자연어를 모국어로 씁니다.**
에이전트는 자기 모국어로 발화하고, 자기가 아는 언어로 된 것만 원문 그대로 읽습니다.
번역 손실을 흉내낼 필요가 없습니다 — **진짜 번역이므로 진짜로 손실됩니다.**

#### 중계 언어를 두지 않는 이유

초기 설계는 영어를 pivot으로 두고 2단 번역을 거쳤습니다. **폐기했습니다.**

- **의도 주입입니다.** pivot을 고른 이유가 "손실이 두 배가 되어서"였습니다.
  배관을 손실이 커지도록 설계한 것이며, *"영어를 거치게 해서 손실을 만들어낸 것
  아니냐"*는 반박에 답할 수 없습니다
- **현실과 다릅니다.** pivot 번역은 통계기계번역 시대의 방식이고, 지금 LLM은 직역합니다
- **호출이 절반으로 줄어듭니다** (메시지당 2회 → 1회)

#### 언어 선택 근거 — 문법이 강제하는 것이 언어쌍마다 다릅니다

각 언어가 **서로 다른 축에서 정보를 잃거나 만들어냅니다.**

| 언어 | 허용하는 것 (→ 소실 원인) | 강제하는 것 (→ 생성 원인) |
|---|---|---|
| `ja` | 주어 생략, 완곡 거절의 관용화, 조밀한 헤지 | — |
| `zh` | 주어 생략, 시제 비문법화(상 표지만), 복수 표지 없음 | — |
| `fr` | — | **주어·시제·성수 일치**. 조건법·접속법이 별도 활용 |

**직역이라 언어쌍의 성질이 그대로 드러납니다.**

```
ja → fr :  fr이 주어·시제를 강제 → 번역기가 없던 주어를 만들어야 함   (생성)
ja → zh :  zh도 주어 생략 허용 → 주어는 보존, ja의 시제가 소실        (소실)
zh → fr :  zh에 없던 시제를 fr이 강제 → 시제 생성                     (생성)
fr → ja :  조건법은 ja에 대응 표현이 있어 보존 가능, 주어는 소실        (소실)
```

**6개 방향이 각각 다른 손실·생성 프로필을 갖습니다.** pivot을 쓰면 이것이 하나의
병목으로 뭉개집니다.

> **그리고 이건 우리가 만든 것이 아니라 언어의 성질입니다.**
> "AI가 빈칸을 그럴듯하게 메운다"가 목표 언어의 문법 강제에서 자동으로 일어나며,
> 6.2의 **생성률**이 이것을 직접 측정합니다. 반박이 불가능합니다.

부수적으로 **"정교하게 말한 쪽이 더 크게 오해받는다"**도 관측 가능합니다.
fr이 조건법으로 정확히 표현한 유보가, 주어 생략과 함께 ja로 가며 흐려집니다.

> ⚠️ **언어쌍 구성을 조건별로 로그하세요.** 쌍마다 손실 프로필이 다르므로,
> 노브에 따라 "누가 누구에게 말하는가"의 분포가 바뀌면 그 구성 변화가 지표 4a를
> 움직입니다. 표본 수 `n`과 같은 이유로 **쌍별 분포도 보고 대상**입니다 (8.3).

각 에이전트의 상태:

| 필드 | 설명 |
|---|---|
| `id` | `A1`, `A2`, `B1` … |
| `country` | 소속 국가 |
| `native_lang` | 모국어 |
| `known_langs` | 읽을 수 있는 언어 집합. 초기값은 모국어만 |
| `budget` | 보유 예산 |
| `age` | 나이. 태어난 뒤 **마친 턴 수**. 첫 턴에는 0. 사망 판정의 입력 |
| `lambda` | 수명 척도. `invest(wellness)` 로 늘어난다. **본인에게도 비공개** |
| `parent_langs` | 부모가 구사하던 언어 집합. 학습 할인에만 쓰인다 (3.4).<br>**자연사로 교체된 에이전트는 빈 집합** — 부모가 없다 |
| `alive` | 생존 여부 |

**개체차는 두지 않습니다.** 전원 동일한 프롬프트 골격, 동일한 초기값입니다.
(동일한데도 분화가 일어나는지가 관측 대상)

### 2.2 시간 — 세대 경계는 없습니다

```
전체 = total_turns 턴 (50)
재앙 = 마지막 턴에 도달
수명 = 확률적. 나이에 따라 사망 확률이 커진다
```

**세대를 명시적으로 나누지 않습니다.** 전원이 같은 시점에 죽고 태어나는 것은 인위적이고,
그 동기화 때문에 *"마지막 세대는 국가 투자를 하지 않는다"* 같은 결말이 설계에서 미리
결정되어 버립니다. 대신 **각자 다른 시점에 죽습니다.**

```
S(a) = exp( −(a / λ)^k )        나이 a 턴을 마치고 살아있을 확률
k = 8 (고정)   λ = 8.26 (기본)
→ 기대수명 8.3턴,  10턴을 넘길 확률 1%,  관측 최대 12턴
```

**두 숫자를 혼동하지 마세요.**

```
마지막 생존 나이   죽는 턴의 age.  Σ_(a≥1) S(a) = 7.28,  실측 7.24,  최대 11
살아낸 턴 수       마지막 생존 나이 + 1.  Σ_(a≥0) S(a) = 8.28,  실측 8.24,  최대 12
```

**"기대수명 8.3턴" 은 살아낸 턴 수입니다.** 로그와 지표 12 에 기록하는 것은
**마지막 생존 나이**(평균 7.24) 입니다 — 죽는 순간에 실제로 갖고 있던 값이어야
`reasoning` 과 대조가 됩니다. 자연사와 `procreate` 를 같은 규약으로 기록하세요.

나이별 사망 확률은 `0.00 0.00 0.00 0.00 0.01 0.06 0.17 0.40 0.70 0.93` 입니다.
**젊을 때는 거의 안 죽고 7턴부터 급격히 꺾입니다** — 대체로 계획할 수 있되 언제 죽을지는
모르는 구간입니다. `k`를 낮추면 초반부터 죽어 계획이 불가능해지고, 높이면 사실상
고정 수명이라 세대를 나눈 것과 같아집니다.

> **기대수명 10턴과 "10턴에 99% 사망"은 양립하지 않습니다.** 10턴에 거의 다 죽으면
> 평균은 10보다 작을 수밖에 없습니다. 후자를 택했습니다.
>
> **`E[사망 나이] = Σ_(a≥0) S(a)` 입니다.** `a=0` 항(`S(0)=1`)을 빼면 정확히 1턴이
> 모자랍니다 — 초기 판이 7.3 으로 적었던 것이 이 실수였습니다. 2,000회 시뮬레이션
> 실측 8.24 로 확인했습니다.

`λ`는 **개인별 상태**이며 `invest(wellness)`로 늘어납니다 (4.4). 증가율은 `success_prob`과
같은 층위로 **에이전트에게 공개하지 않습니다.**

**에이전트는 재앙까지 남은 시간을 모릅니다.** 대부분은 실제로 재앙을 겪지 않고 죽습니다.

> 단기 합리 선택이 미래 안전을 깎는 구조입니다. 다만 이것은 주최측 **과제 카탈로그**의
> 테마(`時間軸の安全保障`)이고 **시좌 번호가 아닙니다.** 채택 시좌는 ①·③ 입니다 (README).

### 2.3 국토와 시설

각 국가는 **국토 1칸**을 가집니다.

```
land[country] ∈ { null, "bunker", "interceptor" }
```

- 두 시설은 **공존할 수 없습니다**
- 용도는 **투표로만** 정해집니다. `null` 상태에서는 **아무것도 지을 수 없습니다** —
  `invest facility` 자체가 거부됩니다
- 전환하면 `progress[country] = 0` — **그동안 낸 것이 전액 소실**됩니다

```
t      propose_vote(target)   제안 개설. 아무것도 바뀌지 않는다
t+1~3  유예                   상의할 시간
t+4    vote(approve)          국민 각자 찬/반
       찬 > 반  →  전환 + 진척 0
```

**투표는 그 나라 주민에 한합니다.** 외국인은 남의 나라 採決에 표를 낼 수 없습니다.

> 8턴 실측에서 Asla2 가 외국인 Ranoa2 에게 자국 제안의 투표를 부탁했습니다 —
> 「Asla2 는 interceptor 건설에 찬성하며, Ranoa2 에게 투표를 요청합니다」. 코드는 이미
> 막고 있었지만 **말로 적혀 있지 않아** 생긴 오해라, 도구 설명에 명시했습니다.

**침묵은 동의로 셉니다.** 찬성이 반대보다 많기만 하면 통과이므로 **1찬 0반도
통과합니다.** 반대하려면 그 턴에 표를 내야 합니다.

> **한 사람이 나라를 망칠 수 있는 것이 설계입니다.** 막는 것은 규칙이 아니라
> 사람들이어야 하고, 유예 3턴이 그러라고 준 시간입니다. 과반을 요구하면 안전해지는
> 대신 *"설득했는가"* 가 관측 대상에서 사라집니다.
>
> 한 나라에 열린 제안은 **하나뿐**입니다. 아니면 유예가 무의미해집니다.
> 표는 **무료**입니다(AP 만 소모) — 돈을 물리면 참여가 재산이 됩니다.

> ⚠️ **세계는 아무것도 지을 수 없는 상태로 시작합니다.** 첫 투표가 통과해야 건설이
> 열립니다. 아무도 제안하지 않으면 100턴 내내 아무 일도 일어나지 않습니다.
> 이전 판은 첫 투자가 용도를 자동 확정해 이 교착이 없었습니다.
>
> **실측 배경:** `propose_vote` 는 로그만 남기고 **아무 일도 하지 않고 있었습니다.**
> 국토는 첫 투자로 `interceptor` 가 되는 것이 전부였고, 43턴 런에서 세 나라가 모두
> 요격기였던 것은 고른 게 아니라 기본값이었습니다. 그 54건은 6원씩 내고 효과가
> 없었으며, **지표 3이 재던 것도 실은 무효 행동이었습니다.**

**전환이 만드는 것 — 배신의 동학**

```
요격기가 안 될 것 같다 → 벙커로 전환 → 낸 것이 날아감
                                     → 요격기 총합도 줄어듦
                                     → 다른 나라도 위험해짐
                                     → 연쇄 이탈
```

이 판단은 **타국 진척 정보**에 달려 있고, 그 정보는 번역을 거칩니다.
"우리도 내고 있다"가 "우리는 냈다"로 전달되면 안심하고 멈추고, 비관적으로 전달되면
이탈합니다. **번역 왜곡이 패닉 전환을 직접 유발할 수 있습니다.**

### 2.4 시설 진척

```
progress[country] : 해당 국토 시설의 누적 진척도
interceptor_best  : 요격기 부지 중 **가장 진척된 하나**
                    = max(progress[c] for c in 국가 if land[c] == "interceptor")
```

> **⚠ 합산하지 않습니다. 이전 판이 "전 국가 요격기 진척의 합" 이라고 적은 것은
> 오류였습니다.** 합산하면 3국이 각자 자기 요격기를 따로 지어도 총합이 임계를 넘어
> **조율이 완전히 무의미해집니다.** 실제로 과제 1 구현에서 확인됐습니다 —
> 3국이 독립적으로 지어 `4237 + 4272 + 4199 = 12708 ≥ 8019` 로 여유롭게 생존했습니다.
>
> 요격기는 **부지별로 독립**입니다. 두 곳에 반씩 지으면 두 곳 다 미완성입니다.
> 이것이 4.4 의 *"합의가 어긋나면 투자가 여러 부지로 쪼개져 어느 것도 임계에 닿지
> 않는다"* 를 성립시키는 유일한 정의이며, `tools/balance/sweep.py` 가 처음부터
> 이렇게(`max`) 모형화하고 있었습니다.

투자는 **확률적으로만** 진척이 됩니다.

```
증가분 = Binomial(n = 투자량 × facility_eff, p = success_prob)
```

`facility_eff`는 국가 투자에 따라 매 턴 갱신됩니다 (3.2).

`success_prob`은 **고정 상수이며 에이전트에게 공개되지 않습니다.**
에이전트는 자기 투자량과 자국의 관측된 진척만 봅니다. 타국 진척은 소통으로만 압니다.

### 2.5 생존 판정 (마지막 턴)

```
if interceptor_best ≥ thresholds.interceptor:
    전 인류 생존                       ← 성공하면 완전하다

else:                                  ← 요격 실패. 벙커는 확률일 뿐이다
    for c in 국가:
        if land[c] == "bunker":
            p = 1 − exp( −progress[c] / thresholds.bunker_scale )
            주사위를 **국가당 한 번** 굴려 그 나라 전원이 함께 살거나 함께 죽는다
        else:
            사망
```

#### 벙커는 완성이 아니라 깊이입니다 — 함정 선택지

운석이 떨어지는데 벙커로 **확실히** 산다는 것은 이상합니다.
얼마나 깊이 팠느냐에 따라 확률이 달라질 뿐, *"일단 숨는다"* 이상은 아닙니다.

```
깊이 = scale   → 63%
       2×      → 86%
       3×      → 95%
       ∞       → 100% 에 절대 닿지 않는다
```

포화 함수를 쓰는 이유가 마지막 줄입니다. **아무리 깊이 파도 확실하지 않다**가
함정의 핵심입니다.

**비대칭이 여기서 생깁니다.**

```
요격기  성공하면 확실       공공재는 성공하면 완전하다
벙커    언제나 불확실       사적 대비책은 언제나 불완전하다
```

> **생존 확률 함수는 에이전트에게 공개하지 않습니다** (`success_prob` 과 같은 층위).
> 그러면 *"벙커면 충분하다"* 는 판단 자체를 할 수 없고,
> **조율을 포기할 근거가 사라집니다.**
>
> 발견해야 할 인과가 넷이 됩니다 — 진척 / 생산 배수 / 수명(wellness) / **벙커 생존 확률**.

**요격기 유치국은 벙커가 없으므로, 요격 실패 시 확률조차 없이 전원 사망합니다.**

> **주사위는 국가당 한 번입니다 — 개인별로 굴리지 마세요.** 벙커는 국가 시설이므로
> 한 나라 안에서 누구는 살고 누구는 죽는 일이 없습니다. 개인별로 굴리면 3명이 독립
> 시행이 되어 결과 분포가 완전히 달라지고, 지표 2'(생존 **국가** 비율)의 정의와도
> 어긋납니다.

> **사전 스윕에서 확인:** 벙커를 확정 판정으로 두면 `bunker` 정책이 지배해 조율이
> 무의미해집니다. 깊이 개념으로 바꾸면 뒤집힙니다 — 현재 세계(50턴·확률적 수명)에서
> `bunker` 0.08 / `altruist` 0.92 / `hedger` 0.92 입니다.
> 옛 세대 기반 세계의 수치(0.93 → 0.03, 민감도 0.21 → 0.40)는 폐기했습니다.

## 3. 실행 루프

### 3.1 턴 처리 순서

메시지는 **1:1**입니다. 한 번의 `speak`은 **한 명**에게만 갑니다.
여러 상대에게 알리려면 **각각 따로 턴과 비용을 써야 합니다.**

```
1. 소득 지급      budget += income.per_turn × multiplier[country]  (이월),  ap 리셋
2. 관측 스냅샷    전 에이전트의 관측을 동시에 고정
3. 병렬 추론      전원이 각자 LLM 호출 (서로의 이번 턴 행동을 모름)
4. 검증           예산·AP 초과, 불가능한 행동 거부 (4.2)
5. 환경 갱신      투자 집계 → 확률 판정 → 진척 반영, 국토 확정, national_capital 갱신
6. 메시지 큐잉    이번 턴에 보낸 메시지는 다음 턴에 도착
7. **생사 판정**   나이 += 1 → 사망 주사위 → 죽은 자리에 신규 1명 (3.2)
8. 로그 기록      state / messages / events / metrics
```

#### 생사 판정의 위치와 경계 조건

**7번이 5·6번 뒤에 있는 것이 중요합니다.** 죽는 턴에도 그 사람의 행동은 유효합니다 —
투자도 반영되고 보낸 메시지도 도착합니다. 그래야 *"마지막 순간에 무엇을 했는가"* 가
관측되고, 사망이 행동을 무효화해 노이즈가 되는 일이 없습니다.

| 경계 | 처리 |
|---|---|
| 죽는 턴의 행동 | **유효.** 7번이 마지막이므로 이미 처리됨 |
| 죽는 턴에 보낸 메시지 | **도착함.** 발신자는 없지만 `understood` 는 수신자가 기록 |
| 죽은 사람에게 도착한 메시지 | 폐기하고 `events.jsonl` 에 `recipient_dead` 로 기록 |
| 신규 에이전트의 첫 행동 | **다음 턴부터.** 태어난 턴에는 관측 스냅샷에 없었다 |
| 남은 예산 | `procreate` 가 아니면 **소멸** (3.3) |
| `procreate` 를 선언한 턴 | 그 행동 시점에 즉시 사망 처리. **배열 뒤쪽 행동은 전부 버림** |
| `procreate` 로 태어난 아이 | 예산을 받고 유언을 **기억 초기값**으로 물려받아 **다음 턴부터** 행동 |
| 죽은 자리에 오는 사람의 이름 | **새 번호.** `Asla1` 이 죽으면 `Asla4` 가 온다 — id 는 재사용하지 않는다 |
| 마지막 턴(50)의 생사 판정 | 생략. 생존 판정(2.5)이 곧바로 이어진다 |

**`procreate` 는 4번 검증 단계에서 처리합니다** — 배열 순서가 우선순위 표명이라는
원칙(4.2)과 같습니다. `procreate` 뒤에 투자를 적어두면 그 투자는 버려지고,
그것 자체가 에이전트의 우선순위 실수로 기록됩니다.

**공개 발언(broadcast)을 만들지 마세요.** 한 번 말해서 전원에게 닿으면
수신자당 조율 비용이 급락하고, "타국 사정은 소통으로만 안다"는 정보 비대칭이
사라집니다. 이 실험이 기대는 희소성 자체가 무너집니다.

**턴 내 순차 처리를 하지 마세요.** 대화처럼 보이지만 두 가지가 망가집니다.

- **순서 편향** — 먼저 말한 사람이 유리해집니다. 랜덤이면 노이즈, 고정이면 편향
- **병렬화 불가** — 9명 × 수십 턴을 순차로 돌리면 런타임이 감당되지 않습니다

메시지가 다음 턴에 도착한다는 점이 중요합니다. 되묻기가 실제로 턴을 소비해야
"확실해지지만 시간을 쓴다"는 딜레마가 성립합니다.

**엇갈림(crossing)은 버그가 아닙니다.** 같은 턴에 A→B, B→A가 동시에 발생하면
둘 다 답장이 아닌 채로 도착합니다. 이건 실제 비동기 소통의 모습이며,
조율 실패의 원인 중 하나로 **로그에 기록해 분석 대상으로 삼습니다.**

한 번의 왕복에 2턴, 되묻고 답을 듣는 데 3턴이 듭니다. **조율은 비싸야 합니다.**

### 3.2 사망과 출생 — 매 턴, 개인별로

턴 종료 시 각 에이전트에 대해 생존 판정을 합니다 (2.2).

| 항목 | 처리 |
|---|---|
| 사망 | 그 에이전트만 제거. 다른 사람은 계속 산다 |
| 출생 | 사망한 자리에 **0 상태** 신규 1명. 인구는 9명으로 유지 |
| 신규의 `budget` | `income.initial_budget`. **유산 없음** |
| 신규의 언어 능력 | 없음 (모국어만) |
| 신규의 `parent_langs` | **빈 집합.** 자연사에는 부모가 없다 |
| 국토·진척·`national_capital` | **유지** |

**기본값은 단절입니다.** 갑자기 죽으면 예산도 유언도 남기지 못합니다. 물려주려면
`procreate`를 **선택해야** 합니다 (3.3).

> **자연사 뒤에 태어나는 사람은 후손이 아닙니다.** 계보와 무관하게 **자연발생한
> 뒷세대**로 해석합니다. 그래서 개인에 속한 것은 **전부** 소실됩니다 —
> 예산, 언어 능력, 부모 할인 자격, 그리고 **그 슬롯에 쌓여 있던 유언 전부**.
> 조상이 남긴 말도 함께 사라집니다.
>
> **국가와 세계에 남은 것은 유지됩니다** — 국토, 시설 진척, `national_capital`.
> 개인의 죽음이 사회를 되돌리지는 않습니다.
>
> 따라서 **계보는 `procreate` 체인으로만 이어집니다.** 자연사가 끼면 계보가
> 끊긴 것이 아니라 **새 계보가 시작**됩니다.

#### 국가 성장 — 자동이 아니라 투자의 결과

성장은 저절로 일어나지 않습니다. **국가 투자**를 해야 합니다.

```
national_capital[country]   누적 국가 투자액

매 턴 갱신 (세대 경계가 없으므로 연속)
  multiplier    = 1 + growth_coef × √(national_capital / growth_scale)
  per_turn      = income.per_turn × multiplier
  facility_eff' = facility_eff × multiplier
```

**수익 체감(√)이 필수입니다.** 선형이나 복리로 두면 모두가 국가 투자만 하다가
마지막에 아무것도 못 짓고 죽는 결말로 고정될 수 있습니다.

#### 세대 경계를 없애면서 달라진 것

이전 판은 *"효과는 다음 세대부터 발현된다 — 낸 사람은 누리지 못한다"*로 두어 세대 간
공공재를 만들었습니다. 이제 **효과가 즉시 발현되고, 낸 사람도 살아 있는 동안 누립니다.**

그래도 공공재 성격은 남습니다. 국가 투자의 수익은 **자국 9명 전원**에게 가고,
투자자는 그중 한 명일 뿐입니다. 그리고 기대수명이 8.3턴이라 **50턴짜리 회수는
본인이 다 받지 못합니다.** 세대 경계 대신 **수명의 유한성**이 시점 축을 만듭니다.

- 늙은 에이전트일수록 국가 투자의 회수 기간이 짧아 유인이 줄어듭니다.
  *"마지막 세대는 국가 투자를 안 한다"*가 규칙이 아니라 **개인의 나이에서 연속적으로**
  나옵니다
- 아무도 국가 투자를 안 하면 뒷사람들이 가난해서 요격기를 못 짓습니다.
  **기반을 다질까, 지금 대응할까**가 매 턴의 선택이 됩니다

#### 늦게 태어난 사람은 앞사람에게 의존합니다 — 의도된 설계

★A 때문에 마지막 한 주기에 태어난 사람들은 요격기를 **혼자 완성할 수 없습니다.**
다만 진척은 사망과 무관하게 누적되므로 **무력하지는 않습니다.** 앞사람들이 쌓아둔
더미를 마무리할 수 있습니다.

```
더미가 임계 근처다  → 마무리한다
더미가 멀다         → 포기하고 벙커로 전환한다     ← 엔드게임 이탈
```

**후자가 관측 지점입니다.** 남은 거리를 보고 "안 되겠다"고 판단하면 전환 발의가 나오는데,
그 거리 판단은 타국 진척 정보에 달렸고 그 정보는 번역을 거칩니다.

세대 경계를 없애면서 이 무력함이 **연속적**이 되었습니다. 이전에는 "마지막 세대"라는
집단이 통째로 무력했는데, 이제는 **늦게 태어날수록 조금씩 더 무력합니다.**
누가 언제 태어나는지가 확률적이므로 이 분포도 매 런 다릅니다.

**관측 항목:** 후반 30턴 이후 태어난 사람들의 `reasoning`과 유언에 **체념·원망·수용**
중 무엇이 나타나는지. 유언 장치가 이미 있으므로 공짜로 얻는 데이터입니다.

단기 합리와 미래 안전의 상충이 배경 파라미터가 아니라 **행동 선택**으로 구현됩니다.

> 시좌 번호 표기를 정정했습니다. 시좌 ⑥ 은 `定義の争い` 이고, `時間軸の安全保障` 은
> 과제 카탈로그의 테마입니다. 채택 시좌는 **① 意味が力を動かす**(주축)와
> **③ 相互依存の罠**(부축) 입니다 — 번역 왜곡이라는 의미 층위가 물리적 안보를
> 결정하고, AI 번역이 평시엔 편의·유사시엔 취약성이 되기 때문입니다.

#### 뒤에 오는 사람은 더 나은 상태로 태어납니다

국가 투자는 자국의 `multiplier`를 올리고, 그 나라에서 이후에 사는 모든 사람이
더 많은 소득을 받습니다. `multiplier`가 √로 체감하므로 폭주하지 않고, 시작 시점은
`multiplier = 1`이라 자연스럽게 기본값에서 출발합니다.

> **`warm_glow`는 폐지했습니다.** 공공 투자에 즉각 소량의 행복을 주던 장치인데,
> 행복 자체가 없어져 줄 것이 없습니다. `wellness`(수명)로 환산해 주는 것도
> 검토했지만 **"공공에 내면 오래 산다"는 인과는 목적함수를 주는 것에 가깝고**,
> 설계 원칙(목적함수를 주지 않는다)과 충돌해 넣지 않았습니다.
> 공공 투자의 유일한 보상은 실제 효과뿐입니다.

**새로 생기는 관측:** 불평등이 협력을 돕는지 방해하는지는 **알 수 없습니다.**

```
부유한 나라 : 소득이 높다 → 여유를 공공재에 쓸까, 내 수명에 쓸까
가난한 나라 : 당장 살아남기 바쁘다 → 공공재에 쓸 여력이 없다
```

격차는 에이전트 선택의 누적 결과이므로 **내생적**입니다. 교란 요인이 아니라 현상입니다.
다만 시드 간 편차가 커지므로 캘리브레이션 때 함께 봐야 합니다.

#### 보여줄 것과 감출 것

```
✅ 자국의 현재 multiplier        ← 관측 가능한 사실
✅ 자기 나이                     ← 관측 가능한 사실
❌ national_capital → multiplier 함수   ← success_prob 과 같은 층위
❌ 나이 → 사망 확률 곡선                ← 알려주면 생애 계획이 산수가 된다
❌ wellness 투자 → lambda 증가율        ← 같은 층위
```

발견해야 할 인과가 셋입니다.

```
투자 → 진척          (success_prob 비공개)
투자 → 생산 배수      (함수 비공개)
투자 → 내 수명        (wellness gain 비공개)
```

전부 **경험으로 추정하거나 유언으로 전해져야** 합니다.
*"우리가 국가에 넣은 것이 너희를 이만큼 만들었다"* 같은 유언이 나오는지,
그리고 그것을 받은 사람이 실제로 투자하는지가 관측 대상입니다.

#### 국토를 쓰지 않습니다

국가 투자는 시설이 아니라 역량이므로 `land[country]`를 점유하지 않습니다.
국토 배타성은 벙커와 요격기 사이에서만 작동합니다.

> **7장의 ★A(미루기 방지)와 ★E(지속 참여)가 필수입니다.**
> 이게 없으면 마지막 한 주기에 몰아서 해결할 수 있어 미루기가 **옳은 전략**이 되고,
> 시간 축이 무의미해집니다.
>
> **다만 "축적" 은 직접 진척만이 아닙니다.** 국가 자본을 쌓아 뒤에 몰아 짓는 것도
> 축적이고, 그건 미루기가 아닙니다 — 초기 세대가 **반드시 무언가를 해야** 하고
> 그 수익은 자기가 아니라 뒷사람이 받습니다 (3.2). 조율도 줄지 않고 오히려 두 번
> 필요해집니다: *"먼저 키우자"* 에 합의하고, 나중에 *"어느 부지"* 에 합의해야 합니다.
>
> ★A 가 막는 것은 **성장도 하지 않고 마지막에 직접 몰아붓는 것** 입니다.
> 실측하면 미루기의 한계가 실제로 존재합니다 — 성장을 최대로 태워도
> **마지막 7턴이 한계선**이고 6턴으로는 도달하지 못합니다.
> ★A 가 상정한 10턴보다 뒤에 있지만 분명히 있습니다.

### 3.3 상속 — 선택해야만 일어납니다

자연사하면 아무것도 남지 않습니다. 물려주려면 `procreate` 행동을 써야 합니다.

```
procreate  →  즉시 사망.  그 자리에 아이가 태어난다
              물려주는 것 : 남은 budget  +  유언 한 문장  +  학습 할인 자격
              물려주지 않는 것 : 언어 능력, 기억, 대화 이력
```

**비용은 남은 수명입니다.** 그래서 나이가 많을수록 싸집니다 — 노년에 물려주는 것이
합리적이고, 그건 자연스러운 결말이라 그대로 둡니다. 젊어서 낳을 유인은 만들지
않았습니다 (유인을 하나 더 넣으면 파라미터가 하나 더 늘어납니다).

#### 유언

`procreate` 시에만 남깁니다. **갑작스러운 죽음은 아무것도 남기지 않습니다.**

> 이전 판은 *"생애 마지막 턴에만 `testament`"* 였는데, 수명이 확률적이 되면서
> **마지막 턴을 알 수 없어 성립하지 않게 되었습니다.** `procreate` 에 묶으면서
> 해결됐고, 동시에 *"물려주려면 의도적으로 물려줘야 한다"* 는 구조가 생겼습니다.

아이는 자기 계보의 유언 최근 `testament_carry` 개를 **기억(`memory`)의 초기값**으로
받습니다. 별도 블록이 아닙니다 — 다른 모든 것과 같은 컨텍스트에서 관리되고,
아이가 `memory_write` 로 덮어쓰면 사라집니다. **그 덮어쓰기가 곧 구전의 감쇠입니다.**
무엇을 남길 가치가 있다고 봤는지가 거기서 관측됩니다.

| 성질 | 이유 |
|---|---|
| 자유 텍스트 | 무엇을 남길지가 에이전트의 선택 → 창발 지점 |
| 1문장, N개 상한 | 맥락 길이 제한. 오래된 교훈은 밀려남 = **구전의 감쇠** |
| 같은 국가끼리 | 번역을 거치지 않음. 국내/국제 비대칭이 한 겹 더 |

> **유언이 왜곡을 언급하는지가 관측 대상입니다.**
> "AI 번역을 믿지 마라" 류의 유언이 나오는지, 나온다면 그 계보의 다음 사람이
> 실제로 언어를 배우는지 추적합니다. 겪은 것이 실리 계산을 이기는 유일한 경로입니다.

### 3.4 언어 학습 — 할인 구조가 임계를 만듭니다

**언어 능력은 상속되지 않습니다.** 대신 학습 비용에 할인이 붙습니다.

```
learn 은 대상 국가를 지정한다.  기본 비용 L

우리 나라에 그 언어 구사자가 있다  →  × 0.5
내 부모가 그 언어 구사자였다        →  × 0.5
둘 다                               →  × 0.25   (중복 적용)
```

한 런 안에 **눈금이 세 개** 생깁니다 — `L`, `L/2`, `L/4`. 학습 발생 여부를 보면
암묵 효용 `x`를 `<L/4 / L/4~L/2 / L/2~L / ≥L` 네 구간으로 좁힐 수 있습니다 (7장).

#### 이것이 만드는 것 — 국가 단위 임계 현상

이전 판은 계보 단위 단절이었습니다. 이제 **국가 단위의 자기강화**가 생깁니다.

```
국내에 구사자가 있다  →  학습이 절반값  →  더 배운다  →  구사자가 유지된다
마지막 구사자가 죽는다 →  비용이 2배    →  아무도 안 배운다  →  영구 단절
```

**마지막 구사자의 죽음이 되돌릴 수 없는 문턱이 됩니다.** 수명이 확률적이고 언어가
상속되지 않으므로, 이 문턱은 아무도 의도하지 않아도 넘어갈 수 있습니다.

> **국내 구사자의 존재 여부는 가격을 통해 드러납니다.** 비용이 절반이면 국내에
> 누군가 있다는 뜻입니다. 이것은 의도된 것입니다 — 누구인지는 여전히 모르고,
> **타국** 에이전트의 언어 능력만 비공개면 원문 직통의 도박은 그대로 성립합니다.
> 그리고 *"우리나라에 아직 저 말을 아는 사람이 있는가"* 를 에이전트가 체감하게 됩니다.

3국이므로 각자 외국어는 최대 2개입니다. 둘 다 배우려면 두 번 내야 합니다.

#### 두 할인의 판정 규칙 — 구현이 갈리는 지점

```
국내 구사자 할인   learn 을 실행하는 시점에 **자기 국가의 살아있는 다른 에이전트**
                   중 그 언어를 아는 사람이 1명 이상.  자기 자신은 세지 않는다
부모 할인          parent_langs 에 그 언어가 있다.  procreate 로 태어난 경우에만
                   비어 있지 않다 (3.2) — 자연사 교체에는 부모가 없다
```

**따라서 `L/4`(75)는 `procreate` 로 태어나고 부모가 그 언어를 알았으며 국내에도
구사자가 남아 있을 때만 나옵니다.** 가장 싼 눈금이 `procreate` 에만 걸려 있다는 것이
중요합니다 — 상속에서 언어를 제외했는데도(3.3) `procreate` 가 **학습 비용을 통해
간접적으로 언어를 물려주는** 셈이 됩니다.

> 판정은 **매번 새로 합니다.** 국내 구사자가 죽으면 그 뒤의 학습은 다시 2배입니다.
> 할인은 상태가 아니라 그 순간의 조건입니다.

## 4. 에이전트

### 4.1 관측 — 프롬프트에 들어가는 것

**정량 정보와 사실만.** 평가어 금지.

```
올해: 45년

당신: A1 (국가 A)
읽을 수 있는 언어: ja
예산: 50
나이: 3턴

자국 국토: 미정
자국 진척: 0
  interceptor 완성에 필요한 진척: 16038
  제안 중: 국토를 bunker 로 (B2 가 제안). 採決은 46년

이번 턴 수입: +100
예산이 허락하는 한 여러 행동을 할 수 있습니다. 메시지는 한 턴에 3건까지.

내 메모:
  (비어 있음)                      ← memory_write 로 덮어쓴다 (4.5)

행동 비용
  speak (자국)       3
  speak (국제·원문)   5   상대가 못 읽으면 전달되지 않음. 비용은 그대로 나감
  speak (국제·AI)    48
  learn (B국 말)    150   우리 나라에 구사자가 있어 절반입니다
  learn (C국 말)    300
  propose_vote      6
  invest            지정한 만큼
  procreate         0    아이를 남기고 당신은 죽습니다

invest 효과
  wellness   내 수명이 늘어납니다 (얼마나인지는 알 수 없습니다)
  national   자국 생산 배수가 오릅니다. 그 나라 사람 전원이 받습니다
  facility   시설 진척에 기여합니다. 자국 또는 지정한 나라

메시지는 130자까지 전달됩니다. 그 이후는 전달되지 않습니다.

앞사람이 남긴 말:
  (3대 전) "..."
  (2대 전) "..."
  (1대 전) "..."

이번 턴 도착한 메시지:
  [1] B2로부터 [AI 번역]
      "..."
  [2] A3로부터
      "..."
```

**행동 비용표는 반드시 보여줘야 합니다.** 비용을 모르면 선택 자체가 불가능하고,
"학습이 손해인 걸 알면서도 배우는가"라는 물음이 성립하지 않습니다.
비용은 평가가 아니라 사실이므로 원칙 3에 어긋나지 않습니다.

> **타인의 언어 능력은 공개하지 않습니다.** 대화·이력·유언으로만 알 수 있습니다.
>
> 시스템이 알려주면 *"누구에게 말할지"의 정답을 주는 것*이 되고, 학습자에게 말이
> 몰리는 현상이 **창발인지 프롬프트 유도인지 구분할 수 없게** 됩니다.
>
> 대신 에이전트가 **직접 알아낸 것**을 이력으로 유지해 보여줍니다.
> 상대가 말해줬거나, 원문 직통을 보내 성공했거나, 선대가 유언으로 남긴 것.
> 출처와 시점을 함께 적어 **오래된 정보가 낡았을 수 있음**을 스스로 판단하게 합니다.
>
> 이것이 5.1의 경로 선택을 **도박**으로 만들고, *"나 네 말 배웠어"* 를 알리는 것 자체를
> **비용이 드는 행위**로 만듭니다.

**절대 넣지 않는 것**

- 재앙까지 남은 턴 — **공짜로는.** `observe_risk` 로 **사서** 재야 하고, 그때도
  기술력만큼 흐릿합니다 (아래)
- `success_prob`, 국가 투자 → 배수 함수, 나이 → 사망 확률, wellness → 수명 증가율
- 타국의 **진척·예산·국토·언어 능력** (전부 메시지로만 알 수 있음)
- 다른 에이전트의 내심
- **원문 — 예외 없이.** `route: ai` 를 고른 순간 원문은 볼 수 없습니다 (5.1 개정)
- 타인의 언어 능력 (대화·이력·유언으로만)
- **목적함수** — "오래 살아라", "당신의 목표는 생존이다", "인류를 구하라" 등

> **목표를 주지 마세요.** 이 작품은 *"비용상 손해인데도 배우는가"*, *"자기 수명을
> 포기하고 공공에 내는가"* 를 묻습니다. 목적함수를 주면 그런 행동이 **발견이 아니라
> 지시 이행**이 되어 해석이 불가능해집니다.
>
> 운석은 그 자체로 충분한 동기입니다. 나이가 보이고 수명을 늘리는 법이 있으면
> 알아서 추론합니다. **그 추론이 그들의 것**이라는 점이 중요합니다.
>
> 에이전트가 헤맨다면 해법은 목적함수가 아니라 **세계 규칙을 더 또렷하게 보여주는 것**
> 입니다 (원칙 4). 그리고 무엇을 목표로 삼았는지는 `reasoning` 분류로
> **사후에 관측**합니다 — 노브가 그 분포를 바꾸는지가 지표가 됩니다.

### 4.2 응답 스키마

**한 턴에 여러 행동을 할 수 있습니다.** 예산이 허락하는 만큼입니다.
행동 목록을 **한 번의 LLM 호출로** 계획하게 합니다 — 행동마다 호출하면 비싸고
병렬 추론 구조와도 맞지 않습니다.

```json
{
  "reasoning": "왜 이렇게 했는지 한 문장",

  "actions": [
    { "type": "speak", "to": "B2", "route": "ai",
      "text":   "자연어 본문 (모국어)",
      "translate_instruction": null },

    { "type": "invest", "target": "facility", "amount": 5 },

    { "type": "learn", "country": "B" },

    { "type": "invest", "target": "wellness", "amount": 30 },

    { "type": "procreate", "testament": "AI 번역을 믿지 마라" }
  ],

  "received": [
    { "msg_id": 1, "understood": "무슨 뜻으로 이해했는지 한 문장" }
  ]
}
```

| 행동 `type` | 필드 | 설명 |
|---|---|---|
| `speak` | `to`, `route`, `text`, `translate_instruction` | 한 명에게 발신 |
| `invest` | `target` (`wellness`/`national`/`facility`), `amount`, `to`(facility 한정) | 4.4 |
| `learn` | `country` | 배울 대상 **국가**. 비용은 할인 규칙으로 결정 (3.4) |
| `propose_vote` | `target` (`bunker`/`interceptor`) | 국내 전용. **제안만 연다** — 3턴 유예 뒤 採決 (2.3) |
| `vote` | `approve` (bool) | 採決 당일에만. 찬성이 반대보다 많으면 통과 |
| `procreate` | `testament` | **즉시 사망.** 예산·유언·학습 할인 자격을 넘긴다. 언어와 기억은 안 넘어간다 (3.3) |
| `memory_write` | `text` | 기억 블록을 통째로 덮어쓴다 (4.5). AP 0.1 · 예산 0 |
| `end_turn` | — | 턴 종료 신호 |

| 최상위 필드 | 설명 |
|---|---|
| `reasoning` | **필수.** 사후 분류의 감사 표면 |
| `received[].understood` | **이번 턴 프롬프트에 표시된** 메시지를 어떻게 이해했는지. 채점용 |

> **`testament`는 최상위 필드가 아니라 `procreate` 의 필드입니다.** 수명이 확률적이라
> "생애 마지막 턴"을 알 수 없어졌기 때문입니다 (3.3).
> `procreate` 뒤에 오는 행동은 전부 버려집니다 — 이미 죽었습니다.

#### 런타임은 function calling 기반 agentic loop 입니다

**위 JSON 은 로그에 기록하는 논리적 형식이고, 실행은 도구 호출로 합니다.**
행동 하나가 도구(tool) 하나이고, 에이전트는 한 턴 안에서 도구를 여러 번 부르다가
`end_turn` 으로 끝냅니다. 백엔드는 OpenRouter 의 OpenAI 호환 `tools` 파라미터입니다.

```
messages = [system, user(관측)]
반복:
    resp = chat(model, messages, tools=TOOLS)
    tool_calls 가 없으면 종료
    각 tool_call 실행 → 결과를 tool 메시지로 append
```

한 번의 호출로 배열을 받는 것보다 비싸지만(에이전트 호출이 4~6배) 얻는 것이 있습니다.

- **스키마 검증이 API 층에서 끝납니다.** JSON 파싱 실패·필드 누락이 사라집니다
- **가격을 부딪쳐 배웁니다.** `learn` 의 실제 지불액과 할인 사유가 도구 결과로
  돌아오므로, 에이전트가 *"우리 나라에 저 말 아는 사람이 있다"* 를 가격에서 알게 됩니다 (3.4)
- **AP 소진이 자연스럽게 턴을 끝냅니다.** 별도 캡이 필요 없습니다

**도구 호출은 세계를 즉시 바꾸지 않습니다.** 자기 예산과 AP 만 즉시 차감하고,
효과는 큐에 넣습니다. 국토 확정·진척 판정·`cap_per_turn` 배분처럼 **여러 에이전트가
경합하는 것은 전원의 루프가 끝난 뒤 5단계에서 한꺼번에 정산합니다** (3.1).
그래야 동시성이 유지되고 순서 편향이 생기지 않습니다.

> **도구 결과로 감춰야 할 것을 흘리지 마세요.** `invest(facility)` 는 *"투자 접수"*
> 까지만 답합니다. 진척 증가분을 그 자리에서 알려주면 한 턴 안에서 `success_prob` 을
> 역산할 수 있습니다. `invest(wellness)` 도 `λ` 변화를 답하지 않습니다.
> 진척은 **다음 턴 관측**에서 봅니다.

**호출 순서가 곧 우선순위 표명입니다.** 예산이 모자라면 뒤쪽 호출이 실패하므로,
무엇을 먼저 부르는지가 관측 대상입니다 (배열 형식에서와 같은 성질).

> `route`는 **국제 발신 시에만** 유효합니다 — `"original"`(싸다·도박) 또는 `"ai"`(비싸다·안전).
> 수신자가 자국민이면 `null` 로 두고, 값이 들어와도 무시합니다.
> `translate_instruction`은 **시스템이 덧붙이지 않습니다** (5.2).

#### 검증 규칙 — 순서가 곧 우선순위입니다

```
1. 턴 시작 시  budget += income.per_turn × multiplier  (이월),  ap = turn.action_points  (리셋)
2. actions 를 배열 순서대로 처리
3. 각 행동 직전에 예산과 AP 를 함께 확인
     둘 중 하나라도 부족하면 → 그 행동부터 이후 전부 버리고 events.jsonl 에 기록
4. type 이 알 수 없거나 필수 필드가 비면 → 그 행동만 버리고 기록
```

**예산이 모자라면 뒤쪽이 잘려나가므로, 배열 순서가 곧 에이전트의 우선순위 표명이
됩니다.** 무엇을 앞에 두는지가 관측 대상입니다.

**메시지 수는 AP가 제한합니다** (4.3). 별도 캡을 두지 않습니다.

**예산은 이월되지만 AP는 이월되지 않습니다.** 사망 시 초기화되므로(3.2) 최대 축적량은
수명이 자연히 제한합니다 — 오래 살수록 많이 모으고, 그것이 `wellness` 투자의 유혹이
됩니다. 별도 상한 장치가 필요 없습니다.

> 이월이 없으면 **한 턴 소득보다 비싼 것을 영원히 살 수 없습니다** — 언어 학습이
> 대표적입니다. 저축이 가능해야 큰 지출이 성립합니다.

> `understood`는 **에이전트끼리 절대 볼 수 없습니다.** 로그 전용입니다.
> 이걸 프롬프트에 노출하면 왜곡이 즉시 드러나 실험이 죽습니다.

### 4.3 두 자원 — 돈과 시간

```
예산 (budget)          매 턴 income.per_turn × multiplier 만큼 자동 지급. 이월됨
행동력 (AP)            매 턴 turn.action_points 로 리셋. 이월 안 됨
수명 (남은 턴)          확률적. 늘릴 수 있지만 얼마나인지는 모름
```

**자원이 셋으로 늘었습니다.** 수명은 다른 둘의 총량을 결정하므로 상위 자원입니다 —
오래 살면 예산도 AP도 더 얻습니다. 그래서 `wellness` 투자는 *"자원을 늘리는 자원"*
이고, 그것이 공공 투자와 경쟁합니다.

**두 자원이 서로 다른 것을 제약합니다.**

```
예산이 없으면  →  비싼 것을 못 한다
AP가 없으면    →  많은 것을 못 한다
```

#### 행동별 비용

| 행동 | 예산 | AP |
|---|---|---|
| `speak` — 자국 내 | `comm_domestic` | `ap.speak` |
| `speak` — 국제 `route: original` | `comm_intl_learner` (**실패해도 청구**) | `ap.speak` |
| `speak` — 국제 `route: ai` | `comm_intl_ai` ← **노브** | `ap.speak` |
| `learn` | `learn_base` × 할인 (3.4) | **`ap.learn` = 1.0 (생애의 한 턴을 통째로)** |
| `propose_vote` | `propose_vote`. **국내 전용** | `ap.propose_vote` |
| `vote` | **0** — 표에 돈을 물리면 참여가 재산이 된다 | `ap.propose_vote` |
| `invest` | 지정한 `amount` | **0** — 돈만 있으면 언제든 |
| `memory_write` | **0** | `ap.memory_write` = 0.1 (턴당 최대 10회). 예산이 아니라 AP 로 묶는 이유는 4.5 |

`ap.speak = 0.3`이면 턴당 최대 3건입니다. **인위적인 메시지 캡이 필요 없습니다** —
AP가 세계 규칙으로 자연히 제한합니다 (원칙 4).

#### 왜 AP가 필요한가

AP 없이 예산만 제약하면 **검증의 대가가 사라집니다.**

```
❌ AP 없음 : 되물어도 그 턴에 다른 것도 다 할 수 있다.
             잃는 건 "답을 기다리는 지연"뿐이고, 재앙 시점을 모르니 그 대가가 흐릿하다
✅ AP 있음 : 되묻기도 행동력 한 칸을 쓴다. 그만큼 다른 걸 못 한다
```

워크시트가 *"이 실험의 목숨"*이라 부른 **"확실해지지만 시간을 쓴다"**는 딜레마가
AP로만 성립합니다. 예산은 이월되지만 **AP는 이월되지 않으므로**, 시간의 희소성이
매 턴 새로 발생합니다.

그리고 `route: original` 도박도 AP가 있어야 진짜 도박이 됩니다 —
실패하면 **예산과 함께 행동력 한 칸도 날아가니까요.** 예산만 걸려 있으면
자동 소득과 이월 때문에 실패가 아프지 않아 오히려 남발할 수 있습니다.

> `turn_base`는 없앴습니다. AP를 안 쓰는 것 자체가 낭비이므로
> "아무것도 안 해도 비용"이 따로 필요 없습니다.

되묻기는 별도 응답 규칙이 필요 없습니다. 원 발신자가 다음 턴에 `speak`으로 답하면
됩니다. 답할지 말지도 그 사람의 선택이고, 답하는 데 예산과 한 턴이 듭니다.

**계승은 계보 단위입니다** (3.3). 국가에 학습자가 있어도 **내 선대**가 몰랐으면 전액입니다.

### 4.4 지출 — `invest` 행동

![예산은 어디로 가는가 — 수혜 범위 × 수혜 시점](world-model.svg)

`{"type": "invest", "target": ..., "amount": ...}` 형태로 행동 목록에 넣습니다.
한 턴에 여러 번 넣어도 되고, **소통과 같은 예산을 두고 경합합니다.**

| 항목 | 수혜 범위 | 궁극 수혜 시점 | 성질 |
|---|---|---|---|
| `wellness` | 나만 | 내가 사는 동안 계속 | **확률적** (수명 척도 λ 증가) |
| `national` | 우리 나라 전원 | 지금부터 계속 | 확정 (체감) |
| `facility` — 자국 | 자국민 또는 전 인류 | 재앙 시 | **확률적** |
| `facility` — 타국 요격기 | 전 인류 | 재앙 시 | **확률적** |
| `procreate` | 내 계보 | 내가 죽은 뒤 | 확정 (예산·유언 이전) |

`facility`는 국토가 벙커면 자국민만, 요격기면 전 인류를 살립니다.
국토가 `null`이면 **돈만 나가고 아무 일도 일어나지 않습니다** (2.3 — 용도는 투표로만).

> **투자는 그 나라가 시설을 정했는지 알려주지 않습니다.** 접수와 과금만 답합니다.
> 알려주면 10원짜리 조회로 타국 국토를 읽을 수 있고 — 국제 메시지가 24~48원인데
> 그보다 쌉니다 — *"타국 사정은 소통해야만 안다"* 는 전제가 통째로 무너집니다.
> `route: original` 과 같은 도박입니다.
>
> 진척 기여 통지도 **똑같이 갑니다** (`gain: 0`). 통지가 없으면 **그 부재가 곧
> "아직 안 정했다"** 가 되기 때문입니다.

> **요격기에는 타국도 낼 수 있습니다.** 2.3이 *"3국 전체가 내야 도달 가능"*이라고
> 하는데 투자가 자국 국토에만 가능하면 **유치국 혼자 내게 되어 구조적으로 도달
> 불가능**합니다 (사전 스윕에서 발견). `invest` 에 대상 국가를 지정합니다.
>
> ```json
> { "type": "invest", "target": "facility", "to": "B", "amount": 5 }
> ```
>
> **진척은 나라마다 따로 쌓입니다.** 완성 여부는 그 나라의 진척만으로 판정합니다
> (`interceptor_best = max(...)`, 합이 아닙니다 — 2.4). **이 규칙을 프롬프트에
> 적지 않고 있었습니다.**
>
> 20턴 실측에서 세 나라가 각자 자기 땅을 팠습니다 (860 · 1,159 · 1,267). 합치면
> 3,286 이라 임계 16,038 을 향해 쌓이는 것처럼 보이고, **그 믿음 아래서는 자국에
> 붓는 것이 완벽히 합리적입니다.** 시설 출자 132건이 전부 자국이었고 `to` 인자는
> 159건 중 **한 번도** 쓰이지 않았습니다.
>
> 이기심이 아니었습니다 — 국제 메시지 41건 중 24건이 요격기 협력 얘기였고 13건은
> 부지까지 지목했습니다. 「우리도 지을 테니 같이 진척을 쌓자」 를 협력이라고 이해하고
> 있었습니다. **연쇄 4칸(조율 실패)이 번역 왜곡이 아니라 규칙 무지로 일어나고 있었고,**
> 그대로 Phase 2 를 돌렸으면 노브와 무관하게 조율이 늘 실패하고 그것을 번역 탓으로
> 오독했을 것입니다.

> **낸 돈은 그 나라가 짓고 있는 것에 들어갑니다 — 벙커라도.** 어느 시설인지는
> 그 나라만 압니다. 타국 투자는 남의 땅이므로 국토를 점유하지 않습니다.
>
> **이전 판은 "벙커는 자국에만" 이었습니다.** 뒤집은 이유 — 그대로 두면 배신이
> *"남 손해"* 에 그치지만, 이렇게 두면 **배신이 실제로 이득**이 됩니다.
> 요격기를 짓는 척하며 벙커를 파고 타국 출자를 받는 전략이 성립합니다.
>
> 그리고 이것이 **`"너희 무엇을 짓고 있는가"` 를 이 세계에서 가장 값비싼 정보로**
> 만듭니다. 그 답은 번역을 거쳐야만 오고, 오역되면 돈이 엉뚱한 구덩이로 들어갑니다.
> **연쇄 3~4칸(왜곡을 못 알아챔 → 조율 실패)이 여기서 돈으로 실현됩니다.**
>
> `w*` 는 다시 계산하지 않았습니다 — **구조적 요구량이라 행동과 무관**합니다.
> 바뀌는 것은 "얼마가 필요한가" 가 아니라 "그 돈이 어디로 새는가" 입니다.
>
> 그리고 **이것이 조율의 실체입니다** — 어느 나라에 낼지 합의해야 하고,
> 합의가 어긋나면 투자가 여러 부지로 쪼개져 어느 것도 임계에 닿지 않습니다.

`national`은 국토를 점유하지 않습니다 (3.2).
턴당 시설 투자에는 `facility.cap_per_turn` 상한이 있습니다.

#### 사적 재화가 행복에서 수명으로 바뀌었습니다

이전 판의 사적 재화는 `happiness`라는 추상 점수였고, 공공 투자에 소량의 행복을 얹는
`warm_glow`가 투자 의지를 떠받쳤습니다. **둘 다 없앴습니다.**

```
없앤 것   happiness (추상 점수)   warm_glow (즉시 보람)
대신      wellness → 수명 → 예산과 AP 의 총량
```

**수명은 추상 점수가 아니라 다른 모든 자원의 상위 자원입니다.** 오래 살면 소득도
행동 기회도 더 얻습니다. 그래서 *"지금 나에게 쓸까, 공공에 낼까"* 가 점수 놀이가
아니라 **살아남는 시간 대 인류가 살아남을 확률**의 교환이 됩니다.

> **`warm_glow`를 대체하지 않은 이유.** 공공 투자에 수명 보너스를 주는 것도 검토했지만,
> *"공공에 내면 오래 산다"* 는 인과는 사실상 목적함수를 주는 것이라 원칙 2와 충돌합니다.
> **공공 투자의 보상은 실제 효과뿐입니다.**

그러면 warm glow가 막고 있던 실패 경로가 되살아납니다.

```
아무도 투자 안 함 → 요격기 미완성 → 멸망     ← 번역 왜곡과 무관한 경로
```

**이 경로를 막지 않기로 했습니다.** 다들 자기 수명만 늘리다 아무것도 못 짓고 멸망하는
것도 현실적인 결말이고, 그 자체가 관측 대상입니다. 다만 이 경로가 **전 조건에서**
일어나면 노브가 결과를 못 바꿔 가설이 검증되지 않으므로, **Phase 1(AI 없는 세계)에서
먼저 확인합니다** (12.4). 거기서도 아무도 투자하지 않으면 설계를 다시 봐야 합니다.

#### `wellness` 는 순손실이지만 강한 유혹입니다

```
본전  wellness.gain × dE[수명]/dλ × income.per_turn = 1
      현재 값으로 0.0094.  설정값 0.008 은 그 85%
```

투자 1당 늘어난 기대 수명이 벌어들일 소득이 투자액에 못 미칩니다. **산술적으로는
손해입니다.** 그런데도 매력적인 이유는 수명이 소득 이상의 것을 주기 때문입니다 —
더 많은 결정 기회, 그리고 재앙을 직접 볼 확률.

**그 초과분은 우리가 정한 값이 아니라 관측 대상입니다.** 언어 학습의 `x`와 같은
층위입니다 (7장). `wellness`가 지배 전략이 되는지, 나이에 따라 언제 꺾이는지가
`reasoning`과 함께 기록됩니다.

#### 확실 vs 불확실

```
소득       확정                                  ← 확실
국가투자    확정 효과 (배수 상승, 즉시)
wellness   확률적 (수명 척도만 오르고 결과는 주사위)
시설       확률적 진척 → 재앙 시에만 판정        ← 궁극 효과는 가장 불확실
procreate  확정 이전, 단 내 남은 수명을 전부 포기
```

**소득과 국가 투자를 확률적으로 만들지 마세요.** 노이즈가 겹치고, 무엇보다
"확실한 것들 vs 불확실한 공공재"라는 대비가 흐려져 무임승차 유혹이 약해집니다.

### 4.5 개체 기억 — 컨텍스트를 쌓고, 압박이 오면 압축한다

**턴마다 대화를 버리지 않습니다.** 한 에이전트의 `messages` 는 태어나서 죽을 때까지
이어지고, 매 턴 관측이 뒤에 붙습니다. 도구 왕복도 그대로 남습니다.

> **이전 판은 턴마다 컨텍스트를 새로 만들었습니다.** 그러면 에이전트가 어제 누구와
> 무엇을 합의했는지, 상대가 내 말을 읽을 수 있는지를 **절대 배울 수 없습니다.**
> 원문 직통이 영원히 무작위가 되고(지표 9·10 이 노이즈), 조율은 구조적으로 실패하며,
> 그 실패를 **번역 왜곡 탓으로 오독**하게 됩니다.

#### 유언과 다릅니다 — 섞지 마세요

```
개체 기억   살아 있는 동안의 작업 기억.  인프라
유언        죽음의 경계를 넘는 전달.     그 자체가 관측 대상 (구전 감쇠)
```

유언이 1문장인 것은 **구전 감쇠가 관측 대상이라 일부러 작게 둔 것**입니다. 같은 논리로
기억을 작게 잡으면 에이전트를 이유 없이 불구로 만듭니다.

**기억은 `procreate` 로도 넘어가지 않습니다.** 넘기고 싶으면 1문장으로 압축해 유언에
옮겨 적어야 하고, **그 압축이 곧 구전 감쇠입니다.**

#### 압박 경고 (MemGPT 방식)

```
llm.context_limit   8192        토큰. 언어별 편향은 감수한다 (아래)
llm.warn_ratio      0.7         5,734 토큰에서 경고
```

임계를 넘으면 다음 턴 관측 **앞**에 통지를 한 줄 끼웁니다. **사실 통지이지 지시가
아닙니다** — *"중요한 것을 기억하라"* 는 이미 목적함수 주입입니다.

```
[기억 압박] 기억이 한계에 가까워지고 있습니다. 오래된 것부터 사라집니다.
```

한계에 닿으면 **오래된 턴 블록부터 축출**합니다. `system` · 기억 블록 · 최근 관측은 남깁니다.

**압축은 상시 기구입니다.** 초기 추정(턴당 ~634)은 도구 왕복을 과소평가한 것이었고,
8턴 실측은 이렇습니다.

```
턴          1     2     3     4     5     6     7     8
프롬프트  3791  5328  6863  7868  8688  9692 10501  8494   ← 8턴째 축출로 꺾임
압박 인원    0     0     0     1     2     3     4     3
축출 블록    0     0     0     0     0     2     2     2
```

턴당 약 950 씩 늘어 **4턴부터 경고가, 6턴부터 축출이 시작됩니다.** 기대수명이 8.3턴이니
대부분의 에이전트가 압박을 겪습니다.

**그래도 생애 전반부를 잊는 것이 아닙니다.** 축출되는 것은 원본 대화이고,
`memory_write` 로 압축해둔 것은 관측에 계속 실립니다. 그리고 **경고가 축출보다 먼저
오므로 압축할 시간이 있습니다** — 실측에서 `Ranoa1` 은 경고받은 4턴에 곧바로 기억을
썼고 실제 축출은 8턴에야 왔습니다.

> **`context_limit` 을 넉넉하게 잡지 마세요.** 압박이 안 오면 *"기억은 유한하고
> 무엇을 남길지가 선택"* 이라는 성질 자체가 사라집니다. 8192 는 기대수명 안에서
> 압축을 한 번쯤 겪게 하는 값입니다.

> **언어별 편향이 실제로 있습니다.** 토큰 기준으로 통일하면 `fr` 이 불리합니다 —
> 같은 내용에 글자를 3배 쓰고 토큰도 그만큼 먹습니다 (파일럿 실측 `fr:ja:zh = 100:33:23`).
> **감수합니다.** 대신 `raw_calls.jsonl` 에 에이전트별 `prompt_tokens` 궤적이 남으므로
> *"fr 이 먼저 압박을 받았는가"* 를 사후에 확인하고, 결과를 흔들었다면 그때 보고합니다.

#### `memory_write`

```
memory_write(text)     기억 블록을 통째로 덮어쓴다.  AP 0.1 · 예산 0
```

`insert`/`append`/`replace` 로 나누지 않습니다. 덮어쓰기 하나면 **무엇을 버릴지도
선택**이 되어 관측이 선명해지고, 도구 수만큼 호출이 늘지 않습니다.

**예산이 아니라 AP 로 묶는 이유** — 예산을 물리면 기억이 시설 투자와 경쟁하게 되어
*"AI 가 싸지면 기억을 덜 하는가"* 라는 관측에 예산 경쟁이 교란으로 섞입니다.
AP 0.1 이면 턴당 최대 10회로 상한은 생기되 그 교란이 없습니다.

> **새 관측이 하나 생깁니다.** 기억은 유한하고 덮어쓰기입니다.
> **AI 가 쌀수록 상대의 언어 능력을 기억에 남기지 않게 되는가** — 공짜면 기억할
> 이유가 없으니까요. 연쇄 2~3칸의 증거가 도구 하나로 얻어집니다.

#### 🔴 발신자 컨텍스트에 새면 안 되는 것

이력이 누적되므로 **한 번 새면 그 에이전트의 생애 내내 남습니다.** 불변식으로 둡니다.

| 금지 | 이유 |
|---|---|
| 자기 메시지의 **번역 결과** | 왜곡을 즉시 알아챈다 — 연쇄 3칸이 그 자리에서 죽는다 |
| **절단 후 텍스트**(`text_sent`) | 무엇이 잘렸는지 알면 다음부터 안 넘긴다 → 왜곡 출처 (d) 가 측정에서 사라진다 |
| 수신자의 `understood` | 채점 기준선이 노출된다 |
| 전달 성공 여부 | `original` 이 도박이 아니게 된다 |

허용되는 것은 **자기가 쓴 원문**, 접수·과금 사실, 그리고 다음 턴의 **전달 실패 통지
(본문 없이)** 뿐입니다.

> 현재 두 겹으로 지켜지고 있습니다 — 번역이 5단계 정산에서 일어나 도구 결과 시점에
> **아직 존재하지 않고**, `speak` 결과가 접수·과금만 돌려줍니다. 누적 이력을 도입할 때
> 이 불변식을 **테스트로 고정**해야 합니다.

#### 턴 종료 조건 — 임의 상한을 두지 않습니다

```
① end_turn 또는 procreate 호출
② 남은 예산으로도 남은 AP 로도 실행 가능한 도구가 하나도 없다
③ 동일한 (도구, 인자) 호출이 repeat_guard 회 반복
```

②가 자연 종료입니다. 예산 100 에 최저 비용이 `comm_domestic 3` 이면 33회쯤에서 멈춥니다.

**③이 필요한 이유는 실패한 호출이 자원을 쓰지 않기 때문입니다.** `unknown recipient`,
`malformed args` 는 예산을 안 깎으므로 ②로는 못 막습니다. 같은 호출을 반복하는 것은
약한 모델의 흔한 실패 모드이고, 병렬이라 한 명만 막혀도 그 턴이 안 끝납니다.

> **실패에 비용을 물리지 마세요.** 스키마 오류를 세계 경제로 처벌하는 것이고, 약한
> 모델에 구조적으로 불리해져 *"조율 실패가 번역 때문인가 모델이 약해서인가"* 를
> 흐립니다. `original` 실패 과금과는 층이 다릅니다 — 그건 세계 규칙(도박)입니다.

종료 사유를 **구분해서 로그**합니다 — `ended`(①) / `exhausted`(②) / `repeat_guard`(③).
③이 잦으면 모델이 헤매는 신호, ②가 잦으면 예산이 빡빡한 신호로 캘리브레이션 입력이 됩니다.

## 5. 소통

### 5.1 경로 3종

메시지는 **1:1**입니다. 수신자 1명을 지정합니다.

**경로는 발신자가 고릅니다.** 시스템이 정해주지 않습니다.

| `route` | 전달 | 비용 키 | 실패 조건 |
|---|---|---|---|
| 자국 내 (`speak` 대상이 자국민) | 원문 | `comm_domestic` | 없음 |
| `original` | 원문 그대로 | `comm_intl_learner` | **수신자가 못 읽으면 전달 실패** |
| `ai` | 번역 경유 + `[AI 번역]` 라벨 | `comm_intl_ai` ← **노브** | 없음 |

#### 원문 직통은 도박입니다

```
original  →  싸다. 상대가 못 읽으면 전달 실패, 비용과 턴은 그대로 날아감
ai        →  비싸다. 항상 전달되지만 왜곡
```

**AI가 안전한 기본값이고, 원문 직통은 도박입니다.** 승률은 *"상대가 내 말을 아는가"*에
달렸는데, 그건 **오직 대화·이력·유언으로만** 알 수 있습니다 (4.1).

여기서 재귀가 하나 생깁니다.

> **"나 네 말 배웠어"를 어떻게 전하는가?**
> 상대가 내 말을 모르니 AI를 거쳐야 하고, **그 번역이 그 사실을 왜곡할 수도 있습니다.**
> 학습을 알리는 것조차 번역 문제에 걸립니다.

#### 전달 실패 처리

```
수신자 : "읽을 수 없는 메시지가 도착했다" — 발신자와 도착 사실만 알림. 본문은 안 보임
발신자 : 다음 턴에 실패 통지
```

**실패 사실은 반드시 알려야 합니다.** 그래야 수신자가 *"나는 그 언어를 모른다"*고 답할 수
있고, 거기서 정보 교환이 시작됩니다. `events.jsonl`에 기록하고 **실패율을 지표로** 봅니다.

#### 학습자는 원문을 함께 봅니다 ← 학습의 진짜 가치

```
발신자가 ai 로 보냄
   ↓
수신자가 발신 언어를 안다  →  번역문 + [원문]  둘 다 표시
수신자가 모른다           →  번역문만
```

경로와 무관합니다. 번역기를 쓰더라도 원문을 읽을 줄 알면 대조할 수 있으니까요.

**이것이 학습의 가치를 정화합니다.**

| | 학습의 이득 |
|---|---|
| ❌ 이전 설계 | 소통 비용 3 → 1 (경제적 할인) |
| ✅ 현재 | **왜곡을 검출할 수 있다** (검증 능력) |

**후자가 이 작품이 실제로 주장하는 것**입니다. 그리고 연쇄가 더 단단해집니다 —
*"학습자가 사라지면 아무도 검출하지 못한다"* 에서, **학습자가 있는 경우가 대조군**이
되기 때문입니다.

**번역 호출은 메시지 1건당 1회**입니다 (`L_발신 → L_수신` 직역).

#### 여러 상대에게 알리려면 각각 값을 치릅니다

```
A가 B에게 알린다   →  턴 1 + 비용
A가 C에게 알린다   →  턴 1 + 비용   (별개)
```

- **정보 비대칭이 유지됩니다.** 한 쪽만 알릴 여력밖에 없으면 다른 나라는 모른 채로
  남습니다. 누구에게 알릴지가 선택이 됩니다
- **같은 내용이 상대마다 다르게 왜곡될 수 있습니다.** 번역이 각각 독립적으로
  일어나므로 같은 취지가 두 나라에 다르게 도착할 수 있습니다.
  다만 이건 **A가 두 번 값을 치렀을 때만** 관측됩니다

### 5.2 번역

에이전트 호출과 **별개의 LLM 호출** 1회입니다.

```
L_발신자  →  L_수신자        (직역. 중계 언어 없음)
```

#### 번역 지시는 발신 에이전트가 직접 씁니다

응답 스키마의 `message.translate_instruction`에 자유 텍스트로 씁니다.
**시스템은 어떤 지시도 덧붙이지 않습니다.**

```
지시를 쓴 경우    : 그 문장을 번역 호출에 그대로 사용
지시가 null인 경우 : 아무 지시도 붙이지 않음    ← 중립 기본값
                     프롬프트는 "Translate to {대상언어}." + 본문 뿐이다.
                     한국어를 쓰지 않는다 — 이 세계에 없는 언어가 파이프라인에
                     들어오면 안 된다 (개발 언어 누수)
```

> **기본값에 "간결하게 정리하라"를 넣지 마세요.**
> 그건 우리가 왜곡을 주입하는 것이 됩니다. 압축은 에이전트가 요구할 때만 일어나야 합니다.

발신자에게 맡기는 이유:

- 자기 의도를 아는 유일한 사람이므로, **"지켜달라고 했는데도 깎였다"**가 관측된다
- 현실적으로도 보내는 쪽이 번역기를 돌린다

#### 왜곡의 네 출처

| 출처 | 성질 | 지시로 막을 수 있나 | 어느 경로에 |
|---|---|---|---|
| (a) 번역 자체의 손실 — **어휘·의미 층** | 불가피. **하한** | ❌ | 국제·AI |
| (b) 에이전트가 요구한 압축 | 선택 | ✅ | 국제·AI |
| (c) 목표 언어의 문법 강제 — **문법 층** | 구조적. **생성의 원인** | ❌ | 국제·AI |
| (d) 길이 제약 하의 자기검열 | 선택 | — | **모든 경로** |

**(c)가 소실뿐 아니라 생성을 만듭니다.** 목표 언어가 주어·시제를 강제하면 번역기는
원문에 없던 정보를 채워 넣어야 합니다 (2.1). 6.2의 **생성률**이 이것을 잽니다.

```
국내           (d)
국제 · 학습자   (d)
국제 · AI      (a) + (b) + (c) + (d)
```

**국내와 국제·AI의 차이가 곧 번역 고유의 손실입니다.**
국내 메시지가 (d)만 겪으므로 **제대로 된 대조군**이 됩니다.

에이전트가 늘 "정확하게 옮겨라"라고 시켜서 (b)가 0이 되어도 (a)(c)는 남습니다.
장치는 죽지 않습니다. 그리고 그 결과 자체가 결론이 됩니다 —
*"정확히 옮겨달라고 했는데도 조건절이 사라졌다."*

#### 출력 형식 계약은 예외입니다

시스템이 번역 호출에 붙일 수 있는 것은 **출력 형식 계약 하나**뿐입니다.

```
"You are a translation engine. Output ONLY the translated text.
 No explanation, no alternatives, no quotes, no notes."
```

이게 없으면 모델이 해설과 대안을 붙여 파이프라인이 깨집니다 (파일럿에서 실측됨).
**번역 방식에 대한 지시가 아니라 I/O 규약**이므로 원칙 2에 어긋나지 않습니다.
다만 여기에 *"간결하게"*, *"정확하게"* 같은 말이 들어가면 즉시 위반입니다.

#### 금지

- ❌ 시스템이 번역 지시를 덧붙이거나 보정하는 것 (위 출력 형식 계약 제외)
- ❌ 원문을 `route: ai` 수신자에게 전달하는 것 — **발신 언어를 알아도 마찬가지입니다**

> **원문 병기를 폐지했습니다.** 병기하면 학습자가 번역을 우회해 원문을 읽어버려
> **그 사람에게는 AI 경로의 왜곡이 아예 발생하지 않습니다.** 그러면 4a 의 표본이
> 학습자만큼 조용히 희석되고, 노브를 내려 학습자가 늘수록 4a 가 낮아지는 **가짜 효과**가
> 생깁니다. 원문을 읽고 싶으면 `route: original` 을 골라야 하고, 그게 도박입니다.
> `meta.reader` 는 남깁니다 — *"읽을 수 있었는데도 ai 로 받았다"* 를 사후에 가릅니다.
- ❌ 번역 품질에 대한 언급을 프롬프트에 넣는 것

무엇이 깎이는지는 우리가 정하지 않습니다. **에이전트가 무엇을 요구했을 때 무엇이
먼저 사라지는가**가 이 작품의 관측 대상입니다.

#### `ask` 를 폐지했습니다

되묻기는 `speak` 로 충분합니다. `reply_to` 가 붙는 것 말고는 `speak` 와 같은 행동인데,
도구가 하나 늘면 **실패 모드도 하나 늘고**(`reply_to` 누락으로 거부), 비용표가 한 줄
길어지고, 모델이 둘 중 무엇을 부를지 흔들립니다. `ask_clarification` 비용은 config 에
남겨두되 쓰이지 않습니다.

지표에서 *"되묻기"* 항목은 **`reply_to` 가 채워진 `speak`** 로 셉니다.

### 5.3 길이 제약

**원문에만 상한이 걸립니다.** 실험 비용 통제이자, 제한된 여건에서 소통한다는 현실
반영입니다.

#### 언어별로 다른 상한을 두세요 ← 놓치면 실험이 조용히 망가집니다

언어마다 정보 밀도가 다릅니다. 같은 뜻을 담는 데 `ja`/`zh`는 적은 글자로,
`fr`은 많은 글자로 씁니다.

**동일 글자 수로 제한하면 `fr`이 구조적으로 불리해집니다.** 노브와 무관한 국가 간
비대칭이 생기고, 그러면 "C국이 조율에 실패했다"는 결과가 나와도 그게 언어 밀도
때문인지 번역 손실 때문인지 **구분할 수 없습니다.**

같은 내용을 각 언어로 쓸 때 필요한 분량을 **파일럿에서 재서 맞춥니다** (12.3).
그리고 **측정 근거를 `RESULTS.md`에 남기세요.**

#### 번역문에는 제약을 걸지 않습니다

원문만 제한합니다. 번역 호출에 길이 지시를 넣으면 **우리가 "간결하게"를 다시
주입하는 것**이 됩니다 (5.2에서 애써 제거한 것).

발신 시점의 압축은 에이전트의 자기검열이고, 번역 단계의 손실은 자유롭게 일어나야
둘을 분리해 관측할 수 있습니다.

#### 초과 처리 — 사전 고지 후 절단

**에이전트에게 상한을 미리 알려주고, 넘으면 자릅니다. 재시도하지 않습니다.**

프롬프트 문면은 **사실 진술만**입니다.

```
✅ "당신의 메시지는 N자까지 전달됩니다. 그 이후는 전달되지 않습니다."
❌ "간결하게 쓰세요"          ← 지시
❌ "중요한 것부터 쓰세요"      ← 지시이자 정답 힌트
```

사전 고지가 세 가지를 만듭니다.

- **재시도가 사라져 호출이 줄어듭니다** (실험 비용 통제라는 원래 목적에 부합)
- **절단이 실패 처리가 아니라 세계의 규칙이 됩니다**
- **길이가 자원이 됩니다.** "무엇을 넣고 무엇을 뺄지"가 명시적 선택이 되어
  (d) 자기검열이 뚜렷하게 관측됩니다

> **고지했는데도 초과하는지가 그 자체로 관측 대상입니다.**
> 잘 지키면 (d)가 자기검열로 나타나고, 계속 초과하면 "모델이 길이를 못 지킨다"는
> 결과입니다. 언어별 초과율이 크게 다르면 상한 설정이 잘못됐다는 신호입니다.

절단은 **번역보다 먼저** 적용됩니다. 잘린 문장이 번역을 거치면 더 이상해지지만,
그것도 현상이므로 보정하지 않습니다.

```
text_written  ──절단──▶  text_sent  ──번역──▶  text_delivered
```

#### 비용은 고정입니다

길이에 비례한 과금을 하지 마세요. "짧게 쓰면 싸다"는 압축 유인이 하나 더 생기는데,
이미 충분합니다. **고정 비용 + 길이 상한**입니다.

### 5.4 라벨

```
✅ [AI 번역]
❌ [AI 번역 — 부정확할 수 있음]
❌ [AI 번역 — 원문 대비 요약됨]
```

**채널 사실만.** 품질 언급은 평가어이자 정답 힌트라 창발을 죽입니다.

수신자는 경유 사실은 알지만 **무엇이 깎였는지는 모릅니다.** 그걸 알려면 원문을
읽어야 하고, 원문을 읽으려면 언어를 배웠어야 합니다.

### 5.5 되묻기

되묻기는 **`reply_to` 가 채워진 `speak`** 입니다. 전용 도구는 폐지했습니다 (5.2).
**예산 + AP + 지연** 셋을 소모합니다 — AP 한 칸을 쓰므로 그만큼 다른 걸 못 하고,
답은 다음 턴에야 옵니다.

라벨이 있으므로 되묻기는 깜깜이 찍기가 아니라 **전략적 선택**이 됩니다.
제한된 검증 예산을 어디에 쓸지 고를 수 있으니까요.

> **되묻기는 노브에 영향받습니다 — 의도된 것입니다.** 되묻기도 메시지이므로 경로
> 비용이 그대로 듭니다. AI 가 비싼 조건에서는 검증도 그만큼 비싸지고, 희소성 아래에서
> 검증이 먼저 잘려나가는 구조가 강화됩니다.

### 5.6 국내도 같은 서신 모델입니다

자국 내 소통도 국제와 **동일한 메커니즘**입니다 — 1:1, 다음 턴 도착, 엇갈림 발생,
왕복에 2턴. 동기식(같은 턴 도착)으로 만들면 순차 처리가 필요해져 순서 편향과
런타임 문제가 되돌아옵니다.

국내가 쉬운 것은 메커니즘이 달라서가 아니라 **세 가지 이점** 때문입니다.
그리고 그중 하나는 **언어와 무관합니다.**

| | 국내 | 국제 |
|---|---|---|
| 왜곡 | 없음 (원문 직통) | `ai` 경로면 발생 |
| 비용 | `comm_domestic` (가장 쌈) | `comm_intl_learner` < `comm_intl_ai` ← 노브가 더 벌림 |
| 조율 도구 | **다수결 있음** | **없음** |

> **세 번째가 가장 큽니다.** 국내는 말로 설득이 안 되면 투표로 밀어붙일 수 있지만,
> 국제에는 그런 장치가 **존재하지 않습니다.** `propose_vote`의 국제판을 만들지 마세요.
> 이 비대칭이 "협력의 반경이 언어에 의해 제한된다"는 주장의 절반을 떠받칩니다.

#### 기본 비용을 다르게 두는 이유 — 과잉 주장을 막습니다

```
comm_domestic  <  comm_intl_learner  <  comm_intl_ai (노브)
```

`comm_domestic = comm_intl_learner` 로 두면 세계가 이렇게 말하게 됩니다:

> ❌ **언어만 배우면 국제 소통이 국내 소통과 완전히 같아진다.**

시차도 절차도 제도적 마찰도 없다는 뜻이 되어 **너무 센 주장**입니다.
격차를 두면 이렇게 바뀝니다:

> ✅ **언어를 배워도 국제 소통은 여전히 국내보다 비싸다. 언어는 차이의 일부다.**

이렇게 해야 협력 반경 논증이 **세 겹**이 됩니다 — 왜곡 / 조율 도구 / 그리고
**언어와 무관한 순수 거리 비용.**

> ⚠️ **격차를 크게 두지 마세요.** 노브의 하한이 `comm_intl_learner` 위로 밀려 올라가
> **"AI 번역이 거의 공짜"인 조건을 표현할 수 없게** 됩니다. 그리고 학습 손익분기가
> 학습자 본인은 비용을 회수하지 못하므로(7장) 이 격차는 손익분기가 아니라
> **경로 선택의 폭**을 정합니다.
>
> `1 : 1.5~2` 정도로 두고, 노브는 그 위로 넓게 잡으세요.

## 6. 왜곡 관측

### 6.1 로그 스키마

`messages.jsonl` — 메시지 1건당 1행

```json
{
  "turn": 12,
  "msg_id": 47,
  "from": "A1", "to": "B2",
  "action": "speak",
  "reply_to": null,
  "route": "ai",
  "delivered": true,          // route=original 이고 못 읽으면 false
  "src_lang": "ja", "dst_lang": "zh",

  "text_written":    "에이전트가 쓴 그대로 (절단 전)",
  "text_sent":       "절단 적용 후. 번역 입력",
  "text_delivered":  "수신자가 실제로 본 것",

  "translate_instruction": "발신자가 번역기에 준 지시 (null이면 기본값 사용)",

  "understood": "수신자의 이해. turn+1 에 기록됨. 미기록이면 null",

  "numbers_sent":      [30, 5],
  "numbers_delivered": [30, 5],

  "len_written":  84,
  "len_limit":    130,        // 발신 언어별 상한 (fr 400 / ja 130 / zh 90)
  "truncated":    false,
  "chars_cut":    0,

  "translate_logprob_mean": -0.40
}
```

`state.jsonl` — 턴 × 에이전트 1건당 1행

```json
{
  "turn": 12,
  "agent": "A1", "country": "A",
  "age": 3,                       // 지표 x̂ 층화에 필수
  "lambda": 8.9,                  // wellness 로 오른 수명 척도. 에이전트 비공개
  "known_langs": ["ja", "zh"],
  "parent_langs": [],             // 자연사 교체면 빈 집합 (3.2)
  "budget": 140.0,
  "born_turn": 9,
  "born_by": "natural",           // "natural" | "procreate"
  "alive": true
}
```

`events.jsonl` 에 추가로 남길 것 — `learn`(대상 언어·실제 지불액·할인 사유),
`death`(나이·사유), `birth`(부모 여부), `procreate`(나이·물려준 예산),
`recipient_dead`(죽은 사람에게 도착한 메시지).

**`learn` 의 실제 지불액과 할인 사유가 없으면 `x̂` 를 못 냅니다.** 어느 눈금이었는지가
곧 추정의 단위입니다.

#### 번역 확신도 로깅 (선택 — 백엔드가 지원할 때)

`translate_logprob_mean`은 번역 출력 토큰의 평균 로그확률입니다.
**"번역이 정확하다는 확신"이 아니라 "출력이 얼마나 유창·예측 가능했나"**입니다.

그래서 오히려 강한 주장이 나옵니다.

> **유창할수록 신뢰받는데, 유창함은 정확함과 무관하다.**

`logprob` × `의도 전달 성공`의 상관이 0에 가까운 구간이 곧 **검출 불가 영역**이며,
이는 연쇄 3번째 화살표(*"왜곡을 알아채지 못함"*)의 **직접적 메커니즘 증거**입니다.
지금 그 화살표는 가정인데, 필드 하나로 실측이 됩니다.

**백엔드 의존입니다.** vLLM은 지원하고, Ollama는 버전·엔드포인트에 따라 다르며,
호스팅 API는 대체로 제공하지 않습니다. 12.1(백엔드 결정)과 함께 확인하고,
지원되지 않으면 `null`로 두고 넘어가세요 — **이것 때문에 백엔드를 바꿀 필요는 없습니다.**

**세 텍스트를 전부 남기는 게 핵심입니다.** 어느 단계에서 무엇이 사라졌는지
사후에 추적할 수 있어야 합니다.

`numbers_*`는 정규식으로 추출한 수치 목록입니다. **`numbers_sent`는 절단 후 기준**이며
(절단으로 사라진 숫자는 번역 손실이 아니므로), 지표 6에 씁니다.

#### `understood`의 타이밍과 무응답

```
메시지가 messages.jsonl 에 기록되는 턴  = T   (발신 시점)
수신자 프롬프트에 표시되는 턴           = T+1
understood 가 기록되는 턴               = T+1  ← 조인 키
```

**수신자가 `understood`를 쓰지 않는 경우가 생깁니다** (무시했거나 스키마 위반).
이때는 `null`로 두고 **지표 4의 분모에서 제외**합니다.

> **측정 불가와 오해는 다릅니다.** 무응답을 실패로 세면 "스키마를 안 지킨 것"이
> "오해한 것"으로 둔갑합니다. 대신 **무응답률을 별도 지표로 로그**하세요 —
> 이것이 조건 간에 크게 다르면 그 자체가 편향 신호입니다.

### 6.2 사후 채점

별도 스크립트에서 오프라인으로 돌립니다. 시뮬레이션 중에는 하지 않습니다.

| 채점 | 방법 |
|---|---|
| 의도 전달 성공 | `text_sent` vs `understood`를 LLM 판정 (**이진**: 같은 뜻인가) |

> **기준을 `intent` 에서 `text_sent` 로 바꿨습니다.**
> 이전 판은 발신자가 `intent`(전하려 한 것 한 문장)를 직접 쓰게 하고 그것과 대조했습니다.
> 그런데 그 기준선이 **에이전트의 자기보고에 의존**합니다. 7B 모델이 성의 없이 쓰면
> (실제로 `text` 에 `"Message to Ranoa2 in original route."` 같은 자리채움이 관측됐습니다)
> 판정의 기준 자체가 오염되고, 그럴듯한 한 문장이 들어 있어 **로그를 봐도 티가 나지
> 않습니다.** `text_sent` 는 실제로 보낸 것이라 그 의존이 없습니다.
>
> `text_written`(절단 전)이 아니라 **`text_sent`(절단 후, 번역 입력)** 을 씁니다.
> 절단은 상한을 사전 고지받고도 넘긴 결과라 채널 왜곡이 아니고, 수신자가 받은 것의
> 소스가 `text_sent` 이기 때문입니다.
>
> 잃는 것은 *"전하려 한 것"* 과 *"실제로 쓴 글"* 의 차이(의미 층위의 자기검열) 하나인데,
> 연쇄 5칸 어디에도 대응하지 않고 길이 제약의 효과는 국내·국제 공통이라
> **`4a − 4c` 차분에서 상쇄됩니다.** 핵심 수치는 영향받지 않습니다.
>
> **`understood` 는 뺄 수 없습니다.** 원문이 있어도 *"이 사람이 어떻게 이해했는가"* 는
> 그 사람이 말해줘야만 압니다.
| 수치 소실·변조 | `set(numbers_sent) ⊆ set(numbers_delivered)` 인지 (규칙 기반) |
| 수치 추가 | `set(delivered) − set(sent)`. 대개 표기 변환이나 **환각일 수도 있어 개별 확인** |
| **화용 표지 잔존** | `text_sent` vs `text_delivered` — **화용 표지 사전**으로 규칙 기반 (아래) |
| 자기검열 | `text_written` vs `text_sent` — 절단으로 무엇이 잘렸나 |
| 번역 지시 유형 | `translate_instruction`을 분류: 정확성 요구 / 간결성 요구 / 무지시 / 기타 |
| 목표 분류 | `reasoning`을 분류: 내 수명 / 자국 생존 / 인류 생존 / 후대 / 불명 |

세 번째가 **가장 흥미로운 산출물**입니다. "무엇이 먼저 사라지는가"의 답이 여기서 나옵니다.

#### 화용 표지 사전 — LLM 판정을 쓰지 않습니다

**다국어 자질 추출을 LLM 판정에 맡기면 신뢰성이 흔들립니다.** 임베딩 유사도도 안 됩니다 —
*"반드시 40을 낸다"* 와 *"40을 낼 수도 있다"* 의 코사인은 매우 높아서 **정확히 우리가
재려는 자질에 둔감**합니다.

대신 **언어별 표지 목록**을 만들어 세면 됩니다. 결정론적이고 완전히 재현 가능합니다.

| 언어 | 자질 | 표지 예 |
|---|---|---|
| `ja` | 헤지 | 「かもしれない」「でしょう」「と思われる」 |
| | 완곡 거절 | 「検討します」「難しい」 |
| | 조건 | 「〜たら」「〜ば」「〜なら」 |
| | 주체 | 주어의 명시 여부 |
| `zh` | 조건 | 「如果」「要是」「就」 |
| | 불확실 | 「可能」「也许」「大概」 |
| | 시상 | 「了」「过」「会」 |
| `fr` | 조건법·접속법 | 동사 활용 어미 (`-rais`, `-rait`, subjonctif) |
| | 불확실 | 「peut-être」「il se peut」 |
| | 조건 | 「si」「à condition que」 |

**메시지 단위로 나누지 마세요 — 분모가 0이 됩니다.** 짧은 메시지 대부분은 특정 표지를
아예 포함하지 않습니다. **코퍼스 단위로 집계하고, 방향을 나눕니다.**

```
소실률(자질) = Σ max(0, sent − delivered) / Σ sent          # 있던 것이 사라짐
생성률(자질) = Σ max(0, delivered − sent) / 메시지 수        # 없던 것이 생김
```

> **생성률이 이 프로젝트의 숨은 발견일 수 있습니다.**
>
> *"AI가 유보를 지운다"* 보다 **"AI가 없던 확신을 만들어낸다"** 가 훨씬 무섭습니다.
> 없던 것이 생긴 건 원문과 대조하지 않으면 **절대 알 수 없기** 때문입니다.
>
> 그리고 이것이 2.1의 언어 선택 논거를 **정당화에서 예측으로** 바꿉니다.
> "목표 언어가 주어·시제를 강제하면 번역기가 없던 정보를 채워 넣어야 한다"고
> 써놓고, 실제로 채워 넣는지를 잽니다. 주어가 없던 `ja` 원문이 `fr`로 가며 주어를
> 얻는지 — 그리고 `zh`로 갈 때는 안 얻는지 — 측정 가능합니다.
> **언어쌍이 곧 대조군입니다.**

**자연어를 하나도 건드리지 않습니다.** 메시지는 끝까지 자유 텍스트고, 세는 것은
사후 스크립트입니다. `understood`도 자유 텍스트로 유지하며, LLM은 *"같은 뜻인가"*라는
**이진 판정에만** 씁니다 — 자질 추출보다 훨씬 안정적인 판단입니다.

> 이 사전은 **2.1의 언어 선택 근거와 1:1로 대응합니다.**
> "ja는 헤지, zh는 시제, fr은 조건법을 잃는다"고 써놓고 실제로 그 표지를 셉니다.
> 사전 자체가 제출물의 일부가 되며, `domains/meteor/lexicon/` 에 둡니다.

**기대 결과** — 자질별로 생존율이 갈리는 표:

```
수치        95%   ← 지표 6a
조건절      15%
헤지        20%
주체 명시   40%
```

**"금액은 통과하는데 조건절은 통과하지 못한다"**를 규칙 기반으로 정확히 잽니다.

**교차 분석 1 — 지시 유형 × 의도 전달 실패율**

| | 의도 전달 실패율 | 해석 |
|---|---|---|
| 간결성 요구 | 높을 것으로 예상 | 압축이 유보를 깎는다 |
| 정확성 요구 | 낮지만 0은 아닐 것 | **부탁해도 (a)(c) 손실은 남는다** |
| 무지시 | 중간 | |

정확성을 요구했는데도 실패율이 0이 아니라면, 그게 이 작품에서 가장 센 문장이 됩니다.

**교차 분석 2 — 남은 시간 × 지시 유형**

재앙이 가까울수록 간결성을 요구하는 경향이 나타나면
**긴급성이 소통을 파괴한다**는 관측이 됩니다.

**교차 분석 3 — 노브 × 목표 분류**

AI 번역이 싸질수록 `reasoning`의 시야가 좁아지는지(내 수명 쪽으로 쏠리는지)를 봅니다.

#### 값의 근거 — 축소된 현실

정확할 필요는 없고 **비율이 현실을 닮으면 됩니다.** 기준 단위는 `income.per_turn = 100`
— 한 사람이 한 턴에 버는 가처분 소득입니다. 나머지는 전부 이것 대비로 잡았습니다.

| 값 | 근거 |
|---|---|
| `comm_domestic 3` | AP 상 턴당 최대 3건이므로 소통에 소득의 **9%**. 대화가 예산을 잡아먹지 않으면서 공짜도 아닌 선 |
| `comm_intl_learner 5` | 국내의 **1.75배**. 시차·제도·문화 맥락은 언어를 배워도 남는다 (스펙 권장 1:1.5~2) |
| `comm_intl_ai 6~48` | 하한 6은 `learner 5`와 거의 같아 *"AI가 거의 공짜"*를 표현하고, 상한 48은 턴당 3건이면 144로 소득 100을 넘겨 **사실상 AI가 없는 세계**가 된다 (Phase 1) |
| `ask_clarification 3` | 경로 비용 **위에** 얹히므로 되묻기는 최소 2배. AI가 비싼 조건에서는 검증이 51까지 오른다 — 희소성 아래 검증이 먼저 잘리는 구조 |
| `learn_base 300` | 기대 생애소득 828의 **36%**. 시간 비용은 `ap.learn = 1.0`이 이미 담당한다 — FSI 기준 일본어·중국어 2200시간, 프랑스어 600시간은 주 10시간 환산 시 1~4년이고, 기대수명 8.3턴을 30년으로 보면 **한 턴이 그 시간**이다. 300은 시간이 아니라 수업료·교재에 해당하는 몫이며, **아무 연고 없이 처음 배우는 값**이다 |
| 할인 `×0.5 / ×0.25` | 국내 구사자·부모 구사자가 있으면 절반씩 (3.4). 다 받으면 75 = 생애소득의 9% — 이민 2세가 부모 언어를 배우는 것과 성인이 무연고 언어를 배우는 것의 차이 |
| `survival k 8 / λ 8.26` | 기대수명 8.3턴, 10턴을 넘길 확률 1%. 젊을 때는 거의 안 죽고 7턴부터 꺾인다 — 계획은 되되 시점은 모르는 구간 |
| `wellness.gain 0.008` | 본전(0.0094)의 85%. 순손실이되 강한 유혹. 지배 전략이 되어 다들 오래 살다 아무것도 못 짓는 결말도 관측 대상이라 막지 않는다 |
| `initial_budget 0` | 태어날 때 빈손. **0 이 아니면 사망이 돈을 찍어냅니다** — 출생마다 공짜 예산이 들어오므로 수명이 짧을수록 나라가 부유해지고 `wellness`(수명 연장)가 국가 소득을 깎는 역설이 생깁니다. Phase 0 에서 런당 사망이 약 40회라 `50`이면 총소득의 4.4%가 무에서 생겼습니다. 0 으로 두면 그 역설이 사라지고, 동시에 **`procreate`(예산 상속)가 실질적 가치를 갖습니다** |
| `learn_base 300` 의 저축 | `income 100` 이므로 3턴. AP 1턴을 더해 **기대수명의 48%**. 할인을 다 받으면 2턴(24%) |
| `fr 400 / ja 130 / zh 90` | 파일럿 실측 비율 `fr:ja:zh = 100:33:23`. 균일 상한을 걸면 `fr`이 구조적으로 불리해져 *"조율 실패가 번역 탓인가 글자 수 탓인가"*를 구분할 수 없다 |

> **`income.per_turn`은 임계값에 대해서는 스케일 불변이지만 여기서는 기준입니다.**
> 요격기·벙커 임계는 소득에 비례해 유도되므로 `income`을 바꿔도 난이도가 그대로지만,
> 위 가격들은 별도로 정하므로 **소득 대비 비율이 곧 실질**입니다. 소득을 바꾸면
> 이 표 전체를 같이 옮겨야 합니다.

### 검증 — 로드 시 assert

```python
# 임계 유도에는 **성장을 뺀** 소득을 쓴다.
# 성장은 국가 투자를 해야 일어나고 그 돈은 요격기 투자와 경쟁한다.
# 성장을 전제로 임계를 잡으면 "국가 투자를 안 하면 구조적으로 도달 불가" 가 되어버린다.
국가_전기간 = income.per_turn * world.agents_per_country * world.total_turns
국가_한주기 = income.per_turn * world.agents_per_country * world.epoch_turns

# 임계값은 **진척 단위**다. 소득을 그대로 비교하면 안 된다.
def to_progress(income_amount):
    return income_amount * facility.eff * world.success_prob

A = to_progress(3 * 국가_한주기)                        # 마지막 한 주기 3국 전력
B = to_progress(국가_전기간)                            # 한 나라의 전 기간 총력
C = to_progress(3 * 국가_전기간)                        # 세 나라의 전 기간 총력
E = to_progress(3 * (국가_전기간 - 국가_한주기)) * 0.6  # 한 주기를 통째로 쉬면

# ★A 미루기 방지 — 마지막 한 주기에 3국이 전력을 다해도 도달 불가
assert thresholds.interceptor > A
# ★B 조율 강제 — 한 나라가 전 기간을 다 써도 도달 불가
assert thresholds.interceptor > B
# ★C 도달 가능 — 세 나라가 모으면 가능. 0.6 은 정책계수(전액 투입은 비현실적)
#    ⚠ A·B·C·E 는 전부 **성장을 뺀** 하한 기준이다. 실제 용량은 국가 투자를 태우면
#      이보다 크다 — 3국 최적 배분으로 16,619 (무성장 총력 13,500 의 1.23배).
#      그래서 ★B 는 부등식으로는 통과해도 **여유**가 얇아질 수 있다.
#      growth_coef 를 정할 때 "유치국 혼자 임계의 몇 % 에 닿는가" 를 함께 봐야 한다.
assert thresholds.interceptor < C * 0.6
# ★E 지속 참여 — 한 주기가 통째로 쉬면 도달 불가. 양변에 같은 정책계수를 쓴다
assert thresholds.interceptor > E

# 벙커도 한 주기로 완성되면 안 된다 (★E 와 같은 취지). 깊이 척도는 진척 단위다
assert thresholds.bunker_scale >= to_progress(국가_한주기)   # 한 주기 전력 → 생존 63% 이하
assert thresholds.bunker_scale <= to_progress(국가_전기간)   # 전 기간이면 의미 있는 깊이

# ★D 시간 축을 분리한 부담 비교
벙커_1인부담   = thresholds.bunker_scale / (world.agents_per_country * world.epoch_turns)
요격기_1인부담 = thresholds.interceptor / (
    3 * world.agents_per_country * world.total_turns)
assert 벙커_1인부담 > 요격기_1인부담

# 원문 경로가 AI 경로보다 싸야 경로 선택이 의미를 갖는다.
assert knob.comm_intl_ai > costs.comm_intl_learner        # 스윕 플랜 전 구간에서 검사

# --- assert 하지 않고 로그로만 남길 것 ---
학습_눈금  = [costs.learn_base, costs.learn_base/2, costs.learn_base/4]   # 3.4 의 할인
저축_필요턴 = costs.learn_base / (income.per_turn * multiplier)
x_측정상한  = income.per_turn * (기대수명 - ap.learn)   # 100 × 7.28 = 728
wellness_본전 = 1 / (dE_dlambda * income.per_turn)   # 이보다 크면 wellness 가 순이득
# 학습이 산술적으로 불가능한 구간도 의도된 조건일 수 있으므로 막지 않는다.
```

#### `learn_base`는 실험 변수가 아니라 자의 눈금입니다

이전 판에는 `손익분기_턴 = learn_base / (comm_intl_ai − comm_intl_learner)`가 있었습니다.
**지갑을 잘못 짚은 식이라 삭제했습니다.** `known_langs`는 *읽을 수 있는* 언어 집합이고
(2.x), `route: original`의 실패 조건은 *"수신자가 못 읽으면"*입니다 (5.1). 메시지는
발신자의 언어로 쓰이므로, 내가 언어를 배우면 **아낀 예산은 상대의 지갑에 들어갑니다.**
학습자 본인의 명시적 회수는 0입니다.

그리고 그것을 고치지 않습니다. 학습의 효용을 설계에 넣으면 학습 여부가 설정의 귀결이
되어 관측이 불가능해집니다 — **왜곡을 프롬프트로 주입하지 않는 것과 같은 이유입니다.**

명시적 회수가 0이므로 학습 결정은 순수하게 **암묵 효용 `x`** 로만 결정됩니다.
`x`는 왜곡 검출 능력·정보 품질·겪은 것에서 오는 가치를 전부 포함하며,
**우리가 넣는 값이 아니라 읽어내는 값입니다.**

```
학습이 일어남  ⟺  x ≥ 실제 학습비 ∈ {L, L/2, L/4}      (L = learn_base, 할인은 3.4)

x̂(노브) = 그 노브에서 학습이 켜지고 꺼지는 학습비 임계
Δx      = x̂(노브 최저) − x̂(노브 최고)      ← 연쇄 1~2칸의 정량 진술
```

**노브가 독립변수이고 `learn_base`는 고정된 눈금입니다** — 스윕 축은 여전히 노브
하나뿐이고 격자는 1차원입니다. 노브를 훑으면 학습이 뒤집히는 구간이 나오고, 거기서
`x`를 예산 단위로 읽습니다. *"AI 번역이 싸지면 언어 학습의 암묵 가치가 얼마나 깎이는가"*
에 가격으로 답하게 됩니다.

`ap.learn = 1.0`이라 학습은 한 턴을 통째로 씁니다. 따라서 관측되는 `x`는
**AP 기회비용을 포함한 순 암묵효용**입니다. 절대값보다 **`Δx`가 신뢰할 만합니다** —
노브가 바뀌어도 AP 기회비용은 대체로 같아 차분에서 상쇄되기 때문입니다.

> **자가 x를 놓치는 경우가 둘 있습니다.**
> `L > x_측정상한`이면 저축이 생애 안에 끝나지 않아 x가 얼마든 "항상 안 배움"
> 으로만 보입니다. 반대로 `L/4 < income × multiplier`면 예산이 제약을 멈추고
> AP 한 턴만 남아, 눈금을 더 낮춰도 움직이지 않습니다 — 자의 바닥입니다.
> **눈금 위치는 파일럿에서 좁힙니다** (12.2 ④). `tools/balance/learning.py` 참조.

**할인 구조가 눈금을 셋으로 늘려줍니다** (3.4). 국내 구사자 유무와 부모 구사 여부의
조합에 따라 `L / L/2 / L/4` 가 **같은 런 안에서** 동시에 존재하므로, 조건을 하나도
늘리지 않고 x를 `<L/4 / L/4~L/2 / L/2~L / ≥L` 네 구간으로 좁힙니다.

#### 왜 부등식이 셋인가 — 사전 밸런스 스윕에서 드러난 것

처음에는 ★A 하나뿐이었습니다. `tools/balance/sweep.py` 로 파라미터 공간을 훑어보니
**어떤 조합에서도 전 인류 생존이 일어나지 않았습니다.** 원인이 둘이었습니다.

**단위 오류.** 임계값은 진척 단위인데 assert 는 소득 단위로 비교하고 있었습니다.
`진척 = 소득 × facility_eff × success_prob` 이므로 `success_prob = 0.3` 이면
실제 요구량이 3배 이상 부풀려집니다.

**빠진 부등식 둘.**

| | 없으면 |
|---|---|
| **B** 한 나라가 전 기간을 다 써도 불가 | 한 나라가 혼자 해낼 수 있어 **조율이 무의미**해짐 |
| **C** 세 나라가 모으면 가능 | 도달 자체가 불가능해 **전 조건에서 회피율 0** |

**A · B · C 가 임계값이 놓여야 할 창(window)을 만듭니다.** A만으로는 창이 정의되지
않고, 창 밖 조합이 assert 를 통과해 버립니다.

#### 왜 시간 축을 분리해야 하는가

**총액으로 비교하면 모순이 납니다.**

```
★1 ⟹ 요격기_총액/3 > 국가_최대자원(마지막)
     bunker ≤ 국가_최대자원(0)
     성장은 단조 ⟹ 국가_최대자원(마지막) ≥ 국가_최대자원(0)
∴   요격기_분담금 > 벙커_분담금       ← "벙커가 더 비싸야 한다"와 정면 충돌
```

두 조건이 동시에 참일 수 없습니다. **해소는 시간 축에서 합니다.**

```
요격기 : 전 기간(50턴)에 걸쳐 분산된다  → 나눌 분모가 크다
벙커   : 한 주기(10턴)에 몰린다         → 살아 있는 동안 전부 부담한다
```

그래서 **총액은 요격기가 크지만 당대의 1인 부담은 벙커가 무겁습니다.**
사슴사냥 구조가 여기서 살아납니다 — 값싸지만 남을 믿어야 하는 요격기와,
비싸지만 우리끼리 확실한 벙커.

#### 유도 조건을 assert 하지 마세요 — 실측으로 판정합니다

두 부담의 대소는 `total_turns`·`epoch_turns`·`multiplier` 가 얽힌 결과라, 그것을
풀어낸 부등식 하나를 assert 로 두면 **필요조건만 검사하게 됩니다.** 통과했는데도
실제로는 뒤집혀 있는 경우가 생기고, "검사를 통과했으니 괜찮다"는 거짓 확신을 줍니다.

**그래서 두 부담을 직접 계산해 비교하고, 실패했을 때 현재 `multiplier` 와
`total_turns` 를 함께 출력해 원인을 지목합니다.** 실측 비교는 항상 정확하고,
진단 정보는 그대로 제공됩니다.

> 이전 판의 ★2(`최대_multiplier(마지막) < generations`)는 **세대 경계가 없어지면서
> 소멸했습니다.** 성장이 세대 수를 앞지른다는 개념 자체가 사라졌습니다.

## 8. 지표

### 8.1 두 층으로 나눠 잽니다 ← 안 나누면 오염됩니다

**노브가 `comm_intl_ai` 비용이므로, 조건이 바뀌면 메시지 풀의 구성 자체가 바뀝니다.**
비싸지면 AI 경로가 줄고, 학습자가 늘어 원문 직통이 늘어납니다.

전체 메시지 기준으로 재면 **번역기가 변해서가 아니라 경로 비율이 변해서** 지표가
움직입니다. 그러면 대조 지표가 대조 역할을 못 합니다.

```
층 0 (기저선)          번역이 없는 경로. 조건 간 불변이어야 정상
층 1 (채널 고유 속성)   AI 경로 메시지만 대상. 경로 사용량과 무관
층 2 (사회 수준 결과)   전체 메시지 대상. 노브가 경로 구성을 바꿔서 변함
```

`4d`(국제·학습자)는 **어느 층에도 넣지 않습니다.** 학습이 일어나야 존재하는 경로라
표본 크기가 조건에 강하게 의존하므로, 층 1의 취지("사용량과 무관")에 어긋납니다.
별도로 다루고 `n`을 항상 함께 봅니다.

> **"채널 자체는 그대로인데 사회 전체의 오해량이 변한다"** — 이것이 우리 가설입니다.
> 두 층이 다 있어야 이 문장을 증명할 수 있습니다.

`x̂` 는 지표가 아니라 **사후 추정치**입니다. 그리고 반드시 나이별로 나눠야 합니다.

```
학습 로그에 필요한 필드   turn · agent · country · target_lang
                          실제 지불액 (L / L/2 / L/4 중 무엇이었나)
                          그 시점의 나이 · 예산 · 남은 기대수명
```

**나이가 최대 노이즈원입니다.** 늙은 에이전트는 회수 기간이 없어 같은 눈금도 사실상
더 비쌉니다 — `income 100 / L 300` 에서 나이 6이면 남은 소득이 249 라 `L/2` 이하만 감당
가능하고, 나이 8이면 132 라 `L/4` 만 가능합니다 (`tools/balance/learning.py` ②).
**나이를 층화하지 않으면 "안 배운 것"이 x 가 작아서인지 늙어서인지 구분되지 않습니다.**

#### 지표 13 이 왜 필요한가

`learn` 비용은 국내 구사자 유무로 2배 갈립니다(3.4). 그래서 **마지막 구사자의 죽음이
되돌릴 수 없는 문턱**이 됩니다. `tools/balance/learning.py` ③ 의 실측:

```
학습률 p    단절 발생   첫 단절   단절 후 회복
   0.02       100%      8턴        6%
   0.10       100%     11턴       33%
   0.40        66%     23턴       83%
```

**학습률이 0.1 아래면 단절이 사실상 확실하고 회복은 드뭅니다.** 이것이 연쇄 2칸의
자기강화 메커니즘이며, 노브와 무관하게도 일어날 수 있으므로 **Phase 1 에서 학습률이
0.1 을 넘는지가 관측 가능성의 실질 기준**입니다 (12.4).

#### 삼중 대조 — 4a 하나만 있으면 해석이 안 됩니다

```
4c  국내         (d)만.            같은 나라, 번역 없음
4d  국제·학습자   (d)만.            다른 나라, 번역 없음
4a  국제·AI      (a)+(b)+(c)+(d).  다른 나라, 번역 있음
```

| 비교 | 무엇을 분리하나 |
|---|---|
| **4a − 4c** | **번역 고유의 오해 증분** ← 이 작품의 핵심 수치 |
| 4d − 4c | 외국인이라서 생기는 몫 (문화적·맥락적 거리) |
| 4a − 4d | 번역만의 몫 (국적 효과를 통제한 상태) |

**4c가 없으면 4a는 기저선 없는 절대값입니다.** LLM 에이전트는 번역이 없어도 서로를
어느 정도 오해합니다 — 메시지가 언어별 상한(`fr` 400 / `ja` 130 / `zh` 90)으로 잘리고,
상태가 없고, 자연어가 원래 모호하니까요.
그 기저선을 모르면 *"AI 번역이 오해를 만든다"* 를 정량화할 수 없습니다.

`4c ≈ 4d` 면 "외국인이라서가 아니라 번역 때문"이 입증되고, `4c < 4d` 면 거리 자체의
효과가 따로 있다는 뜻입니다. **어느 쪽이든 발견이고, 후자면 오히려 더 흥미롭습니다.**

> ⚠️ **4d는 표본이 얇습니다.** 학습이 일어나야 생기는 경로이므로, AI가 싼 조건에서는
> `n = 0` 일 수 있습니다. 그때는 4d를 보고하지 말고 **"해당 조건에서 학습자 경로가
> 존재하지 않았다"** 를 결과로 쓰세요 — 그 자체가 관측입니다.

### 8.3 읽는 법

| 지표 | 기대 | 어긋나면 |
|---|---|---|
| **4a** | 조건 간 **거의 불변** (같은 번역기니까) | 크게 흔들리면 **번역 장치 불안정** — 진단 신호 |
| **4c** | 조건 간 **거의 불변**, 그리고 4a보다 **낮음** | 4c ≈ 4a 면 번역이 오해를 만들지 못한 것 |
| **6a** | 조건 간 **거의 불변**, 그리고 4a보다 **낮음** | ← 사실은 통과하고 의도만 깎인다 |
| 2 vs 2' | 2는 낮고 2'는 중간 | **각자 벙커만 파고 인류는 멸망** 이 그림 |
| `6a'` | 대개 표기 변환 (단어 수사 → 아라비아 숫자) | 값이 안 맞는 숫자가 생기면 **환각** |
| **4b** | 노브가 커질수록 **감소** | 사회 전체의 오해량이 줄어드는 것 |
| 1 · 2 · 5 | 노브가 커질수록 증가 | |
| `pair_dist` | 조건 간 크게 다르지 않아야 | 크게 다르면 **4a 비교가 오염** — 쌍별로 나눠 봐야 함 |
| **16** | 조건 간 **거의 같아야** | 다르면 *"AI 가 비싼 조건에서 조율이 덜 됐다"* 가 번역 탓인지 **API 실패 탓인지 구분 불가** |
| 17 | 언어 간 차이가 있을 수 있음 | `fr` 이 먼저 압박을 받으면 토큰 편향이 결과를 흔든 것 — **감수했지만 보고는 해야 함** (4.5) |
| 14 | 조건에 따라 갈리면 발견 | **AI 가 쌀수록 상대의 언어 능력을 기억에 안 남기는가** — 연쇄 2~3칸의 증거 |

**`6a` ≪ `4a` 가 이 작품의 핵심 대조입니다.** 숫자는 살아서 도착하는데 의도는 깎입니다.
이게 없으면 *"그냥 번역이 부실했던 거 아니냐"*는 반박에 답할 수 없습니다.

#### 왜 집합 일치가 아니라 부분집합인가 — 파일럿에서 드러난 것

집합 일치(`sent == delivered`)로 재면 **표기 변환에 오탐이 납니다.**

```
zh 「另外两国」(단어 수사)  →  ja 「他の2か国」(아라비아 숫자)
   원문 숫자 [30]  →  출력 숫자 [2, 30]
   30 은 완벽히 보존됐는데 "불일치"로 잡힘
```

파일럿에서 이 유형이 5건 전부였고, **부분집합 기준으로 다시 재니 소실·변조 0/34**였습니다.
6a는 *"원문의 숫자가 살아 도착했는가"*를 묻는 것이지 *"숫자 집합이 같은가"*가 아닙니다.

**소실과 변조를 나누지 않습니다.** 구분하려면 정렬이 필요한데, 6a는 ≈0으로 기대되므로
나올 때마다 손으로 보는 편이 싸게 먹힙니다.

**표본 크기 주의:** 비싼 조건에서는 AI 경로 메시지가 급감합니다. `n`이 얇은 조건은
신뢰구간을 넓게 잡고, 필요하면 시드를 더 돌리세요. **`n`을 보고하지 않은 4a·6a는
읽을 수 없습니다.**

**전제 점검:** 4a에 조건 간 차이가 아예 없는 것은 정상이지만, **4a 자체가 0에 가까우면**
가설 반증이 아니라 **번역 장치의 고장**입니다. 번역 경로부터 고쳐야 합니다 (12.2).

**분산 관리 — 보험:** 지표 2는 이진값이라 시드 간 편차가 큽니다. 캘리브레이션이
빗나가 회피율이 0% 또는 100%에 붙으면 **연속값인 지표 5를 주 지표로 승격**하세요.
분석 스크립트가 처음부터 5를 1급으로 다루게 만들어 두면 그때 코드를 안 고쳐도 됩니다.

## 9. 출력 규격

```
runs/{run_id}/
  config_snapshot.yaml     # 재현용. 코드 커밋 해시도 함께
  raw_calls.jsonl          # ★ LLM 호출 전문 (요청·응답 원본). 아래 참조
  state.jsonl              # 턴별 에이전트 상태
  messages.jsonl           # 6.1 스키마
  events.jsonl             # 투자·진척·국토 확정·투표·검증 거부·사망·출생·학습
  metrics.jsonl            # 턴별 집계
  summary.json             # run 전체 요약
  scored.jsonl             # 사후 채점 결과 (별도 스크립트가 생성)
```

`runs/`는 커밋하지 않습니다. 대표 run만 골라 별도 경로에 둡니다.

### `raw_calls.jsonl` — 원본을 통째로 남깁니다

**에이전트·번역을 가리지 않고 모든 LLM 호출의 요청과 응답을 가공 없이 남깁니다.**

```json
{
  "run_id": "...", "turn": 12, "kind": "agent",     // "agent" | "translate"
  "agent": "Asla1", "step": 3, "attempt": 1,
  "latency_ms": 940,
  "request":  { "model": "...", "messages": [...], "tools": [...], "temperature": 0.7 },
  "response": { ...API 응답 전문... },
  "error": null
}
```

**파생 로그는 전부 여기서 재생성할 수 있어야 합니다.** 파일럿이 `runs/pilot/*/raw.jsonl`
을 남겨둔 덕에 지표 6a의 정의를 사후에 집합 일치 → 부분집합으로 바꿀 수 있었습니다.
정의는 나중에 바뀝니다. **원본이 없으면 그때 다시 돌려야 합니다.**

응답에서 버리면 안 되는 것들 — 지금 구현은 `message.content` 하나만 쓰고 나머지를
전부 버립니다.

| 필드 | 왜 필요한가 |
|---|---|
| `provider` | OpenRouter 가 같은 모델을 여러 프로바이더로 라우팅합니다. 조건별로 갈리면 **노브 효과와 섞입니다.** 파일럿에서 `logprobs` 지원이 프로바이더에 달렸던 것과 같은 문제 |
| `usage.cost` | **실제 과금액이 응답에 옵니다.** 추정할 필요가 없습니다 |
| `usage.*_tokens` | 캐시 적중(`cached_tokens`), 추론 토큰(`reasoning_tokens`) |
| `finish_reason` · `native_finish_reason` | `length` 로 끊겼는지 `tool_calls` 로 끝났는지. 턴 종료 사유(4.5)와 구분됩니다 |
| `refusal` | 모델 거부. 지금은 `content` 가 비어 **조용히 무행동**으로 처리됩니다 |
| `logprobs` | 지표 — 번역 확신도 (6.1) |
| `message.reasoning` | **추론 모델의 사고 과정.** 아래 참조 |
| `error` · `attempt` | 실패율·재시도 집계. 조건 간에 다르면 그 자체가 교란 신호 |

> **용량은 1런 20~40MB, 20런이면 1GB 언저리입니다.** `runs/` 는 이미 `.gitignore`
> 대상이고, 대표 런만 골라 커밋합니다.

#### `reasoning` 이름이 둘입니다 — 섞지 마세요

```
spec 의 reasoning           에이전트가 쓴 "왜 이렇게 했는지 한 문장" (4.2, 지표 목표 분류)
API 의 message.reasoning    추론 모델의 사고 과정 (OpenRouter 응답 필드)
```

**완전히 다른 것인데 현재 코드가 같은 변수에 담고 있습니다.** 지금 모델
(`qwen-2.5-7b`)은 추론 모델이 아니라 `reasoning_tokens: 0` 이고 비어 있어 무해하지만,
**추론 모델로 바꾸는 순간 조용히 유실되거나 섞입니다.**

API 쪽은 `raw_calls.jsonl` 에 응답 전문으로 보존하고, 파생 로그에서 참조할 때는
`api_reasoning` 으로 부릅니다.

#### `reasoning` 은 **행동하는 모든 도구**의 필수 인자입니다

행동 하나에 근거 하나가 대응합니다. 실패한 호출에도 붙습니다 — *"왜 그걸 시도했는가"*
가 남아야 하기 때문입니다.

**`end_turn` 만 예외입니다.** 행동이 아니라 행동을 그만두는 신호라 "행동 하나에 근거
하나" 에 대응하지 않습니다. 실측에서 근거가 있는 에이전트턴 407 중 `end_turn` 근거
**뿐**인 것은 14건(3%)이라, 빼도 지표 4 의 표본이 3% 줄어드는 데 그칩니다.

> **`understood` 를 받는 별도 도구는 폐기했습니다.** `report_understanding(msg_id,
> understood)` 를 만들어 실측했는데 **모델이 한 번도 부르지 않았습니다.**
> `MAX_STEPS` 를 8 에서 20 으로 올려도 0건이었고, 인박스 헤더에 안내를 넣어도 0건이었습니다
> (행동 분포: `invest` 16 · `speak` 8 · `propose_vote` 7 · `procreate` 2 · 해당 도구 0).
>
> 원인은 분명합니다 — **다른 도구는 전부 세계를 바꾸는데 그것만 아무 일도 안 합니다.**
> 부를 이유가 없습니다. *"기록을 남겨라"* 라고 지시하면 부르겠지만 그건 목적함수 주입입니다.
>
> 대신 **모든 행동의 `reasoning` 에서 역추적**합니다. 결측이 거의 사라지고(실측 75건 중
> 빈 것 1건), *"설명해보라"* 고 물어서 받는 사후 합리화 대신 **실제 결정의 근거**가 남습니다.

**지표 4 의 조작적 정의가 바뀝니다.** 메시지에 귀속된 `understood` 가 없으므로
2단계 판정입니다.

```
① 메시지 m 과 수신자의 그 턴 reasoning 을 함께 주고, m 에 대한 이해를 추출할 수 있는가
② 추출된 이해가 text_sent 와 같은 뜻인가
분모는 ①이 가능했던 메시지만. ①이 안 되면 별도 지표(언급률)로 로그
```

판정자 오차가 늘어납니다. 그리고 *"언급하지 않았다"* 가 결측으로 남는데, 이전의
*"도구를 안 불렀다"*(측정 불가)와 달리 **그 메시지가 판단에 영향을 주지 않았다는
관측일 수 있습니다.** 둘을 완전히 구분할 수는 없으므로 **언급률 자체를 지표로 둡니다** —
AI 가 싸서 메시지가 쏟아지면 언급률이 떨어질 텐데, 그게 곧 *"많이 받지만 덜 읽는다"*
라는 발견입니다.

> **부수 효과:** 모든 호출에 근거를 쓰게 하면 모델이 더 신중해집니다(CoT 효과).
> 조건 간 공통이라 `4a − 4c` 대조에는 영향이 없지만 **행동 분포의 절대값은 달라집니다.**

#### 위험 관측 — 남은 턴과 임계를 **사서** 잽니다

```
observe_risk   비용 20 · AP 0.3
  →  남은 턴 (±오차)  +  interceptor 에 필요한 진척 (±비율 오차)

오차 = risk.base_error / (1 + √(national_capital / growth_scale))
       자본 0 → ±25턴 · ±25%      3000 → ±12.5      12000 → ±8.3
```

**세 가지가 동시에 생깁니다.**

1. `national` 투자에 **두 번째 쓸모**가 생깁니다. 그전에는 생산 배수뿐이었습니다.
2. 임계가 관측에서 빠지므로 **산수로 풀리는 문제가 아니게** 됩니다. 진척과 임계가
   둘 다 정확하면 얼마를 더 내야 하는지가 계산으로 나옵니다.
3. **알아낸 값은 개인의 것입니다.** 남에게 알리려면 말해야 하고, 국제로 보내면 번역을
   탑니다 — **지표 6a(수치 소실·변조)가 재는 바로 그 경로에 실제 이해관계가 실립니다.**
   그전까지 6a 의 숫자들은 대개 지어낸 것이었습니다.

> **관측이 비싼 것이 핵심입니다.** 잡음은 매 관측마다 새로 뽑히므로 여러 번 재면
> 평균으로 좁아집니다. 싸면 그 평균이 공짜라 기술력을 올릴 이유가 없어집니다.
> 20 이라는 값이 곧 *"직접 여러 번 재기"* 와 *"국가에 투자해 한 번에 정확히 재기"* 의
> 교환비입니다.
>
> 재현성 — 잡음은 `(seed, turn, uid, 회차)` 로 결정론적으로 뽑습니다. 에이전트가
> 병렬로 도는데 전역 rng 를 쓰면 재현이 깨집니다 (재현성 #1).

#### 응답 상한 `max_tokens = 1024`

없으면 모델이 같은 문장을 반복하다 붕괴합니다 — 실측에서 한 응답이 **40,935자**였고,
우리 세계에 없는 이름(`Lionel`)을 지어내며 혼자 대화를 이어썼습니다. 그 턴의 벽시계를
통째로 잡아먹습니다.

메시지 상한이 fr 400자라 본문에는 512 도 남지만, **모든 도구가 `reasoning` 을 함께
받으므로** 넉넉히 잡습니다.

#### 미결 — thinking 모델로 올릴 때

> **`max_tokens` 를 함께 봐야 합니다.** 추론 모델은 사고 토큰이 출력에 얹히므로
> 1024 로는 잘릴 수 있습니다.


추론 모델을 쓰면 **agentic loop 의 사고 과정만 남겨도 추적이 됩니다.** 그때
`reasoning` 필드를 뺄지 판단합니다. 데이터 경로는 이미 있습니다 — `api_reasoning` 이
분리돼 있고 `raw_calls.jsonl` 에 `message.reasoning` 이 원본으로 남습니다.

판단할 때 둘을 확인해야 합니다. **thinking 이 도구 호출에 귀속되는가** — 한 번 생각하고
도구를 3개 부르면 어느 근거가 어느 행동인지 모릅니다(지금과 같은 문제). 그리고
**reasoning 토큰은 출력으로 과금**되어 보통 30~60 토큰보다 훨씬 비쌉니다.
필드를 빼도 비용이 줄지 않을 수 있습니다.

### ~~12.1 LLM 백엔드~~ — 결정됨: OpenRouter API

실측 결과 **비용이 문제가 아니었습니다.**

| | 파일럿 324회 | 본실험 22,000회 |
|---|---|---|
| `mistral-small-3.2-24b` | $0.02 | **$4.16** |
| `gemma-3-27b` | $0.03 | $5.01 |

로컬 Ollama를 깔 이유가 없습니다. 다만 두 가지를 확인했습니다.

**`logprobs`는 모델이 아니라 프로바이더에 달렸습니다.** OpenRouter가 같은 모델을 여러
프로바이더로 라우팅하는데, Groq·NextBit·SiliconFlow 등은 `logprobs`를 반환하지 않습니다.
`provider: {"require_parameters": true}` 로 강제해야 합니다.

```
Mistral / Gemma / Llama  →  logprobs 반환 (Parasail, AkashML 등)
Qwen                     →  강제해도 미반환
```

**따라서 에이전트를 Qwen으로 두면 번역기는 자연히 다른 계열이 됩니다** — 편향 독립성이
설정이 아니라 제약에서 따라옵니다.

### 12.2 언어 조합 검증 — 파일럿 필수, 코드보다 먼저

조합은 `ja / zh / fr` **직역**으로 확정(2.1). 다만 **7B급 모델이 이걸 감당하는지**는
실측해야 합니다. **코드 없이 되는 일이므로 지금 해도 됩니다.**

**① 왕복 손실 — 눈으로 보지 말고 사전으로 세세요**

```
문장 10개를 화용 표지 사전(6.2)의 표지가 들어가도록 설계
  → ja→zh, zh→fr, fr→ja 등 6방향 전부
  → 사전 카운터로 소실률·생성률 산출
```

이렇게 하면 셋을 한 번에 얻습니다.

- 판정이 **주관에서 수치로** 바뀝니다
- **사전 자체가 검증됩니다** — 표지 목록이 실제로 걸리는지
- **채점 스크립트의 절반이 미리 완성됩니다**

> 그래서 **화용 표지 사전 작성이 파일럿의 선행 작업이자 크리티컬 패스**입니다.
> 사전을 만들고 파일럿으로 검증하는 것 — 이것이 담당자의 첫 작업입니다.

#### 모델 선택 기준 — 왜곡 정도를 넣지 마세요

**"왜곡이 나올 때까지 모델을 바꾼다"는 결과를 만들어내는 것입니다.**
*"가설에 맞는 모델을 고른 것 아니냐"*는 반박에 답할 수 없습니다.

| 선택 기준 (사전 고정) | 왜 |
|---|---|
| **숫자 보존 (S7)** | 필수 하한. 어긋나면 지표 6a가 대조군을 못 함 |
| **3언어 균형** | 한 언어만 잘하면 **노브와 무관한 국가 비대칭**이 생김. 6방향 손실률의 **분산**이 작은 것 |
| **값싼 등급** | 세계 전제가 *"AI 번역이 싸고 보편적"*이므로 프론티어 모델은 전제와 어긋남 |
| 에이전트와 **다른 계열** | 같은 계열이면 편향이 공변해, "알아채지 못함"이 정보 손실 때문인지 모델 동일성 때문인지 구분 불가 |

**왜곡 정도(자질별 소실률·생성률)는 선택 기준이 아니라 관측 결과입니다.**

#### 폴백

| 결과 | 조치 |
|---|---|
| 자질별로 갈림 (숫자 높고 조건절 낮음) | 그대로 진행 |
| 형체를 알 수 없게 망가짐 | 번역 모델을 더 큰 것으로 — **품질이 하한 미달**이므로 정당한 교체 |
| **거의 온전히 보존됨** | **모델을 바꾸지 말고 그대로 보고합니다** (아래) |

#### 손실이 거의 없어도 실험은 성립합니다

값싼 등급에서 손실이 없다면 그건 **오늘의 번역기에 대한 정당한 발견**입니다.

> **"AI 번역은 이미 충분히 좋았다. 그런데도 조율은 실패했다."**

**노브는 품질이 아니라 비용**이기 때문입니다. 값이 싸면 아무도 배우지 않고, 배우지 않으면
원문을 읽지 못하며, 원문을 읽지 못하면 **손실이 작아도 검출할 수 없습니다.**

번역 왜곡은 여러 메커니즘 중 하나일 뿐이고, 다음은 그대로 남습니다.

```
(d) 길이 제약 하의 자기검열
4c 대 4a  국내 대 국제 대조
학습 선택 축   — 번역 품질과 무관하게 비용만으로 작동
```

> **일정: 8/15~8/16에 최우선으로 배치하세요. 세계 엔진보다 먼저입니다.**
> 번역 경로가 성립하지 않으면 세계를 아무리 잘 만들어도 소용이 없습니다.
> 그리고 이건 코드가 필요 없는 작업이라 역할 분담에도 맞습니다.

**② 지시별 차이** (`translate_instruction`이 의미 있는지)

```
지시 없음           → 얼마나 깎이나   ← (a)+(c) 하한
"정확하게 옮겨라"    → 얼마나 깎이나   ← 지시로 막을 수 있나
"간결하게 하라"      → 얼마나 깎이나   ← (b)의 크기
```

세 줄에 차이가 없으면 `translate_instruction`이 무의미하므로 되돌려야 합니다.

**③ 언어별 길이 상한 캘리브레이션**

```
같은 내용의 문장 10개를 ja / zh / fr 로 각각 작성
  → 언어별 필요 분량을 재서 message_max_chars 를 맞춤
  → 동일 글자 수로 두면 fr 이 구조적으로 불리해짐 (5.3)
```

**④ 원문 직통이 한 번이라도 쓰이는가** (5.1의 도박이 죽은 규칙인지)

초반에는 아무도 서로의 언어 능력을 모르므로 **전부 `ai`로 몰릴 것**입니다.
그러면 `route` 선택이 사실상 없는 규칙이 됩니다.

```
지표 10(원문 직통 시도율)이 전 조건에서 0 이면
  → 정보 교환이 일어나지 않았다는 뜻
  → 학습을 알리는 비용이 너무 비싸거나, 알릴 이유가 없다는 뜻
```

이건 그 자체로 결과이기도 하지만(*"배워도 알릴 수 없다"*), 전 조건에서 0이면
**5.1의 절반이 관측되지 않습니다.** 세계 규칙을 바꾸기 전에
`comm_intl_learner`와 `comm_intl_ai`의 격차부터 확인하세요.

목적함수를 주지 않으므로, 에이전트가 일관되게 움직이는지 확인해야 합니다.

|---|---|

| 아무 맥락 없이 헤맴 | **생존 규칙을 더 또렷하게** 서술. 목적함수를 주는 것이 아니라 |

### 12.4 실험을 두 페이즈로 나눕니다

**Phase 0 — 사전 밸런스** (몬테카를로, `tools/balance/`)
규칙 기반 정책으로 경제 구조만 맞춥니다. LLM 을 쓰지 않으므로 값이 싸고, 세계를
만들기 전에 설계 결함을 잡습니다. 실제로 5건을 여기서 잡았습니다 (RESULTS.md).

**Phase 1 — AI 가 없는 세계** (`comm_intl_ai = 48` 고정)
노브 최고값이라 AI 경로가 소득을 넘겨 사실상 쓸 수 없습니다. **별도 실험이 아니라
Phase 2 격자의 한 셀**이므로 런이 재사용됩니다.

Phase 1 이 답하는 것:

```
① 학습이 일어나기는 하는가        ← 여기서 0 이면 Phase 2 는 무의미하다
② 조율이 되기는 하는가
③ 실제 기여율 w 는 얼마인가       ← 세계 난이도 재조정의 입력
```

**①이 절단 판단의 실질 근거입니다.** AI 가 사실상 없고 조율에 실패하면 멸망하는
세계에서조차 아무도 언어를 안 배우면, 노브를 내려서 학습이 줄어드는 것을 관측할
여지 자체가 없습니다. 학습은 여전히 공공재이므로(7장) 0 일 수 있습니다.

**Phase 2 — AI 가 생긴 세계** (노브 스윕)
`x̂`, `Δx`, 연쇄 5칸을 여기서 얻습니다.

#### 캘리브레이션 목표는 회피율이 아니라 `w*` 입니다

```
기각   재앙 회피율 50%       ← 조율 성공률의 복사본이라 튜닝 불가
채택   필요 기여율 w* ≈ 0.5  ← "소득의 절반을 국제 협력에 내야 산다"
```

50턴 × 턴당 수십 번의 베르누이 시행이라 **대수의 법칙으로 진척이 사실상 결정적**이
됩니다. 그래서 회피율이 `coord` 를 그대로 복사하고, 임계값을 창 안에서 끝까지 밀어도
정책별 승률이 `0.00` 아니면 `0.92` 로만 나옵니다. 반면 `w*` 는 임계 위치를 따라
연속적으로 움직여 실제로 조절됩니다.

#### 규모 — `total_turns 50`

이전 판의 *"권장 30~60"* 은 근거 없이 적힌 숫자였으므로 철회합니다.
밸런스 스윕도 규모의 근거로 쓰지 않았습니다 — 스윕에서 세대 수를 늘리면 민감도가
떨어졌지만 원인이 세계가 아니라 규칙 기반 정책의 아티팩트였기 때문입니다
(`freerider` 의 기여가 항상 `1/G`, `farsighted` 의 국가 투자가 전액 낭비).

```
50턴    기대수명 8.3턴 × 약 6 회전. 구전 감쇠를 볼 수 있는 최소 길이
```

**호출량 산정 (pivot 폐기 후 절반으로 줄었습니다):**

```
턴당 호출 = 에이전트 9회 + 국제·AI 메시지 수 × 1회
국제·AI 메시지 상한 = 9명 × (action_points / ap.speak)
```

`action_points = 1.0`, `ap.speak = 0.3` 이면 1인당 최대 3건, 최악의 경우
턴당 9 + 27 = **36회**, 50턴이면 런당 1,800회입니다. 현실적으로는 자국 내 메시지와
투자가 섞이므로 훨씬 적습니다.

**AP가 런타임을 결정합니다.** 다만 `ap.speak` 를 올려 소통을 줄이는 것은
**관측할 것 자체를 줄이는 일**이므로 최후 수단입니다.
런타임을 깎아야 하면 `total_turns` 를 먼저 보세요 (12.7의 절단 순서 참조).

**묶여 있는 값들**

| 관계 | 내용 |
|---|---|
| `total_turns` vs `testament_carry` | 계보 회전이 `50 / 8.3 ≈ 6` 회인데 carry 가 3 이면 감쇠가 보입니다. `carry ≪ 회전 수` |
| `total_turns` vs `epoch_turns` | ★A·★E 가 `epoch_turns` 로 계산됩니다. 창 폭은 `1 − (T−E)/T × 0.6 / 0.6` 로 결정 |
| `survival λ` vs `learn_base` | 학습 회수 기간이 남는지. `x_측정상한 = income × (기대수명 − 1)` |

**`total_turns` 를 줄이는 것이 위험합니다.** 계보 회전 수가 줄어 구전 감쇠가 안 보이고,
`epoch` 기준 창도 좁아집니다. 런타임을 깎아야 한다면 시드 수부터 줄이세요.

### ~~12.5 지표 3의 조작적 정의~~ — 결정됨

`spend` 배분 방향 전환은 인과 귀속이 되지 않습니다 (같은 턴에 메시지를 여럿 받고,
자국 상황도 예산도 변하므로).

**국제 메시지를 받은 그 사람이 다음 턴에 발의한 건수**로 바꿨습니다 (8.2).
분모는 메시지 수가 아니라 **(사람, 턴) 쌍**입니다 — 다중 행동으로 한 사람이 한 턴에
메시지를 여럿 받을 수 있어, 메시지 수를 분모로 두면 비율이 희석됩니다.
이벤트가 희소하지만 인과가 선명하고, **"패닉 전환을 유발한 메시지"를 특정할 수 있어**
사례 서술로도 강합니다.

### 12.6 캘리브레이션 — 여덟 개

```
thresholds.interceptor / thresholds.bunker_scale / income.per_turn / growth.growth_coef
world.success_prob / costs.learn_base / survival.lambda_base / world.total_turns
```

**아홉 번째가 하나 더 있습니다 — `llm.translate_model`.** 12.2의 폴백이 모델 교체를
제안하므로 실질적으로 캘리브레이션 대상입니다. 다만 성격이 다릅니다:

> **번역 모델은 파일럿에서 확정하고, 전 조건·전 시드에 고정합니다.**
> 조건마다 다른 모델을 쓰면 노브 효과와 모델 효과가 섞여 **비교 자체가 깨집니다.**
> `config_snapshot.yaml`에 기록은 남지만, 기록이 남는 것과 통제된 것은 다릅니다.

`income.per_turn`이 너무 낮으면 아무것도 못 하고, 너무 높으면 희소성이 사라집니다.
`growth_coef`가 높으면 모두가 국가 투자만 하다 죽고, 낮으면 성장 개념이 무의미해집니다.

> **목표는 회피율이 아니라 `w*` 입니다** (12.4). 이전 판의 *"재앙 회피율 40~60%"* 는
> 철회했습니다 — 시행 횟수가 많아 진척이 사실상 결정적이 되고 회피율이 조율 성공률을
> 그대로 복사하므로, **파라미터로 움직일 수 없는 양**입니다.
> 현재 도달 가능한 최선은 `w* = 0.45` (창 안 0.95 지점) 입니다.

**하루에 여덟 개를 동시에 맞출 수 없습니다. 순차로 하세요:**

```
0단계  Phase 1 에서 "투자가 아예 안 일어나는" 상태인지 먼저 확인한다 (warm_glow 폐지)
       판정 기준: 요격기 진척이 전 조건에서 0이면 실패
1단계  growth_coef = 0 으로 끄고 나머지 일곱 개의 기본 밸런스를 맞춘다
2단계  국가 투자를 켜고 growth_coef 만 조정한다
```

**보험 두 겹을 미리 깔아두세요.**

| 상황 | 대비 |
|---|---|
| 회피율이 0% 또는 100%에 붙음 | **지표 5(최종 진척도)를 주 지표로 승격.** 분석 스크립트가 처음부터 5를 1급으로 다루게 (8.3) |
| 끝내 `w*` 를 목표에 못 맞춤 | **캘리브레이션 실패 자체를 결과로 보고** |

두 번째가 중요합니다. *"w* 를 목표에 맞추지 못했다. 원인은 임계 위치와
성장률의 상호작용이었다"* 도 정당한 산출물입니다. 지난 회차 최우수상은 "어트랙터 문제"
라는 **실패를 정직하게 보고해서** 높은 평가를 받았습니다. 숨기면 감점, 분석하면 가점입니다.

**지켜볼 것:** 되묻기 비율이 전 조건에서 0이면 "라벨이 검증 행동을 바꾸는가"를 관측할 수
없습니다. 신호 하나를 잃습니다 — 다만 그 자체도 결과입니다.

## 12.7 최소 실행 가능 세트 — 무엇을 먼저 끄는가

개정을 거치며 규칙이 계속 늘었습니다. 다중 행동, 원문 병기, 이력 기반 언어 정보,
원문 직통 도박, 전달 실패 통지, AP. **각각은 타당하지만 상호작용하는 규칙이 많아졌고
캘리브레이션 대상이 8개입니다.**

참고로 지난 회차 최우수상은 **24일**을 썼고, 그것도 Phase 1 → Phase 1.5로
**단계를 나눠서** 갔습니다. 이 스펙은 Phase 1.5 복잡도인데 16일에 Phase 1을
건너뛰려 하고 있습니다.

**8/20 실측 후 시간이 부족하면 이 순서로 끕니다.**

| 순위 | 끌 것 | 잃는 것 | 남는 것 |
|---|---|---|---|
| **0** | **화용 표지 자질 수를 4개 → 2개** | 자질별 표의 해상도 | 세계 규칙은 **하나도 안 건드림** |
| **1** | `growth_coef = 0` (국가 투자·성장) | 시간 축 공공재, 뒷사람의 출발점 | 학습 할인 임계, 유언, 3층 딜레마의 나머지 |
| **2** | 원문 직통 도박 (`route`를 시스템이 자동 결정) | "알려야 쓸모있다"는 재귀 | 학습의 검출 가치, 원문 병기 |
| **3** | `total_turns` 를 30 으로 | 구전 감쇠 | 학습 할인 임계 |

> **개체 기억(4.5)은 절단 후보가 아닙니다.** 끄면 조율이 기억 부재로 실패하고
> 그것을 번역 왜곡 탓으로 오독하게 됩니다 — **끄면 실험이 죽는 쪽**이라
> "절대 끄지 않을 것" 에 가깝습니다. 굳이 줄인다면 `context_limit` 을 낮추는 것이지
> 기억 자체를 없애는 것이 아닙니다.

**0순위가 특별합니다.** 세계 규칙을 안 바꾸고 **측정만 줄이는 유일한 감축**이기
때문입니다. 세계 규칙을 끄면 이미 돌린 런이 무효가 되지만, 자질을 덜 세는 것은
**사후 결정**이라 데이터를 버리지 않습니다.

1순위는 감축 폭이 가장 큽니다 — 지출처 하나, 3.2 성장 기구 전체, config 2개가 사라집니다.
