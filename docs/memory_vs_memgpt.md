# MemGPT 와 우리 기억 관리의 차이 (이슈 #37)

논문: Packer et al., *MemGPT: Towards LLMs as Operating Systems*, arXiv:2310.08560.
우리 쪽 기준은 브랜치 `feat/interview` (트리 `fc9f47a`) 의 **코드**입니다.

이 문서는 「우리가 뭘 안 했나」 를 세지 않습니다. 세 칸으로 가릅니다.

```
의도된 차이   그대로 두어야 하는 것 — 바꾸면 관측 대상이 사라진다
안 본 차이    생각 안 해봤을 뿐인 것 — 제안은 여기서만 나온다
못 하는 차이  하고 싶어도 이 실험에서는 불가능한 것
```

## 0. 한 문장

**MemGPT 는 손실을 최소화하는 기계이고, 우리는 손실을 재는 기계입니다.** 두 설계가 같은
부품(문맥 한계 · 압박 경고 · 축출 · 자기편집 메모)을 쓰는데 목적함수의 부호가 반대입니다.
그래서 MemGPT 에서 개선인 것이 우리에게는 대체로 **관측 파괴**입니다 — 다만 전부는
아니고, 그 경계가 이 문서의 본론입니다.

## 1. 두 설계를 나란히

| | MemGPT | 우리 |
|---|---|---|
| 문맥 한계의 성격 | 모델의 **제약**. 넘어서야 할 벽 | 세계의 **규칙**. 여기서 잃는 것이 관측 대상 (spec 4.5) |
| 계층 | main context / external context (RAM ↔ 디스크) | **하나뿐.** 외부 저장소가 없다 |
| 상시 기억 | working context — 고정 크기 읽기·쓰기 블록 | `Agent.memory` 문자열 하나. 크기 상한 없음 ([state.py:23](../core/state.py#L23)) |
| 대화 | FIFO 큐. 0번 자리에 **축출분의 재귀 요약**이 산다 | FIFO 턴 블록. 축출되면 **아무 흔적도 안 남는다** ([agent_loop.py:660](../core/agent_loop.py#L660)) |
| 압박 경고 | 프롬프트 토큰이 창의 ~70% 를 넘으면 시스템 메시지 | 같은 70% (`warn_ratio`). 단 **직전 콜의 실측** 토큰으로 판정 ([agent_loop.py:679](../core/agent_loop.py#L679)) |
| 축출을 누가 | **큐 매니저**(시스템)가 100% 에서 flush. 창의 ~50% 를 비우고 요약을 만든다 | 매 스텝 자동 축출(한계 8192, FIFO). **그리고** 기억을 쓰면 경고선(5,734)까지 추가로 비운다 ([agent_loop.py:684](../core/agent_loop.py#L684)) |
| 되돌리기 | recall storage · archival storage 에서 **검색해 되불러온다** | **없다.** 축출은 되돌릴 수 없다 |
| 기억 도구 | `core_memory_append` / `core_memory_replace` / `conversation_search` / `archival_memory_insert` / `archival_memory_search` — **언제나 열려 있다** | `memory_write` 하나. **덮어쓰기만** 되고 압박선 아래에서는 **목록에 없다** ([tools.py:196](../core/tools.py#L196)) |
| 제어 흐름 | function chaining + heartbeat / yield | 스텝마다 도구 강제(`tool_choice="required"`), `end_turn` 으로 종료 |
| 계보 | 없음 | 자연사할 때 한 문장이 후손에게 간다 ([loop.py:262](../core/loop.py#L262)) |

두 가지를 먼저 정확히 해 둡니다. **우리도 자동 축출을 합니다** — 「MemGPT 만 자동이고
우리는 에이전트가 해야 한다」 는 오해입니다. 매 스텝 `evict(convo, 8192, fixed)` 가 돕니다
([agent_loop.py:816](../core/agent_loop.py#L816)). 다른 것은 **축출이 무엇을 남기는가**입니다 —
MemGPT 는 재귀 요약을 남기고 원본을 recall 에 보관하며, 우리는 아무것도 남기지 않습니다.

그리고 **`memory_write` 는 축출을 막지 않습니다.** 자리를 더 사는 것뿐입니다 (한계 8192
→ 경고선 5,734). 그래서 「적으면 안 잃는다」 가 아니라 「적으면 **더 잃되 고른 것은
남긴다**」 가 정확한 기술입니다.

## 2. 의도된 차이 — 그대로 두어야 하는 것

| # | 차이 | 왜 그대로 두는가 |
|---|---|---|
| I1 | **되돌릴 수 없다** (archival/recall 없음) | 압축에서 잃는 것 자체가 관측 대상이다 (spec 4.5 · 3.3 구전의 감쇠). 검색을 붙이면 재는 양이 0 이 된다 |
| I2 | 축출이 **요약을 안 남긴다** | 요약은 「우리가 대신 압축해 주는 것」 이다. 무엇을 남길지 고르는 일이 에이전트의 행위여야 그 선택을 채점할 수 있다 |
| I3 | `memory_write` 가 **덮어쓰기만** | append 면 누적이라 감쇠가 안 일어난다. 덮어쓰기는 **매번 전량 재기술**을 강제하므로 한 번 쓸 때마다 전사(轉寫) 사건이 하나 생긴다 — 그것이 우리 자다 |
| I4 | 기억이 **돈도 AP 도 안 든다** (`ap.memory_write 0.0`) | 값을 물리면 「AI 가 싸지면 기억을 덜 하는가」 관측에 교란이 섞인다 ([agent_loop.py:249](../core/agent_loop.py#L249)) |
| I5 | 계보 채널 (유언) | MemGPT 에 대응물이 없다. 세대 간 전달을 **기억이 아니라 들은 말**로 두는 것이 3.3 의 요점이다 |
| I6 | 기억이 **상속되지 않는다** | 아이는 빈손으로 태어난다. 물려받으면 감쇠가 계보에서 멈춘다 |
| I7 | 압박 경고가 **사실 통지**다 (지시가 아니다) | 「기억하라」 고 말하면 그 행동이 우리 지시의 귀결이 된다 (spec 4.1 목적함수 금지와 같은 이유) |

### ① 「되돌릴 수 없다」 의 경계는 정확히 어디인가

이슈가 물은 것 — *「자기가 쓴 메모는 되돌릴 수 있고 남의 말은 아니다」 같은 구분이 가능한가.*

**가능하고, 사실 이미 절반은 그렇습니다.** 지금 구조에서 되돌릴 수 없는 것은 **대화**이고,
메모는 애초에 축출 대상이 아닙니다 — system 에 매 콜 새로 실리므로 지워지지 않습니다
([prompts.py:828](../domains/meteor/prompts.py#L828)). 즉 경계선은 이미 「내가 적은 것은
남고, 들은 말은 사라진다」 입니다.

그러니 남은 선택지는 **메모의 이력**(옛 판본으로 되돌아가기)인데, 이것은 붙이면 안 됩니다.
덮어쓰기가 곧 전사 사건이라는 I3 이 무너집니다 — 옛 판본이 살아 있으면 「잃은 것」 이
잃은 것이 아니게 됩니다.

**대신 우리가 붙일 수 있는 것은 관측 쪽입니다.** 판본을 에이전트에게 돌려주지 않고
**로그에만** 남기면(지금 `memory_write` 의 본문은 `raw_calls`·`calls` 에 남습니다,
[agent_loop.py:733](../core/agent_loop.py#L733)) 감쇠를 세대별로 셀 수 있습니다. 세계는
그대로이고 자만 늘어납니다. → 제안 P4.

### ③ 「압축을 거래로 만든 것」 은 옳은 유인인가

MemGPT: flush 는 큐 매니저가 한다. 에이전트가 경고를 무시해도 **자동으로** 비워지고,
그때 재귀 요약이 남으므로 무시의 대가가 「요약으로 뭉개짐」 입니다.
우리: 무시하면 8192 에서 자동 축출되고 **아무것도 안 남습니다.** 쓰면 5,734 까지 더
비워지고 **쓴 것은 남습니다.**

즉 우리 거래는 「적으면 공간이 생긴다」 가 아니라 **「적으면 무엇이 남을지 네가 고른다」**
입니다. 그 방향이 옳습니다 — 유인이 「공간」 이면 아무 말이나 적어도 이득이지만, 실제로
얻는 것은 **선택권**이라 무엇을 적는지가 결과를 바꿉니다.

다만 문구가 그 사실을 말하지 않습니다. 경고문은 「古いものから消えていきます」(오래된
것부터 사라집니다)뿐이고, **쓰면 그 순간 더 사라진다**는 것은 어디에도 없습니다
([prompts.py:170](../domains/meteor/prompts.py#L170)). 에이전트는 자기가 방금 산 것의
가격을 모릅니다. → 안 본 차이 U5.

## 3. 안 본 차이 — 제안이 나올 자리

### U1. 문맥 압박이 **언어에 교락**된다 ★

SYSTEM 이 모국어라 길이가 다릅니다. 도구 스키마는 셋 다 같습니다.

```
                system 추정 토큰    도구      고정비    경고선(5,734)까지 남는 대화 자리
  ja (Asla)          858           2,260     3,118              2,616
  zh (Ranoa)         718           2,260     2,978              2,756
  fr (Miris)       1,757           2,260     4,017              1,717   ← 38% 적다
```

메시지 상한도 다릅니다 — ja 130자 · zh 90자 · fr 400자 (파일럿 길이비에서 나온 값). 추정
토큰으로는 한 통이 각각 43 · 30 · **133** 입니다. **고정비도 크고 한 통도 큰** fr 에이전트는
같은 대화량으로 훨씬 빨리 압박에 닿습니다.

이 실험은 **언어와 나라가 1:1** 입니다 (Asla=ja · Ranoa=zh · Miris=fr). 그러면
「Miris 사람들이 기억을 더 못 한다」 가 나라 정체성과 구분되지 않습니다. `inh30` 에서
Asla 가 벙커를 고르고 Miris 가 요격기를 이끌었는데, 그런 차이를 문맥 용량 차이로
설명할 수 있는지 우리는 아직 안 봤습니다.

> 확인 방법: `raw_calls.jsonl` 의 `usage.prompt_tokens` 을 나라별로 나눠 압박 진입 시점
> (몇 살에 처음 `pressured`)과 `evicted_blocks` 를 비교. 세계를 안 건드리는 검사입니다.

**제안 P1.** 고정비를 언어 간에 맞춥니다. 두 방법이 있고 성격이 다릅니다.

```
① context_limit 을 언어별로 보정      세계 규칙을 나라마다 다르게 만든다 — 나쁘다
② fr SYSTEM 을 줄인다                 같은 사실을 더 짧게 적는 편집 작업. 세계는 안 변한다
```

②가 맞습니다. fr 이 2.4배 긴 것은 규칙이 더 많아서가 아니라 프랑스어가 길어서입니다.

### U2. 축출은 **추정 토큰**으로, 압박은 **실측 토큰**으로 판정한다 ★

`under_pressure` 는 API 가 돌려준 `usage.prompt_tokens` 을 쓰고
([agent_loop.py:679](../core/agent_loop.py#L679)), `evict` 는 `chars // 3` 추정을 씁니다
([agent_loop.py:587](../core/agent_loop.py#L587)). 계수 3 은 「CJK 본문 과소추정 × 영어
스키마 과대추정」 이 상쇄되도록 실측 150콜에서 고른 값입니다 — **전체 평균이 1.01 이
되도록** 맞춘 것이고, 언어별로 맞춘 것이 아닙니다.

지금 도구 스키마 추정은 2,402 토큰인데, 주석이 기록한 실측 대비 비율(1,389 추정 : 909 실측
= 1.53배)이 그대로라면 실제는 1,600 쯤입니다. 라틴 문자인 fr 본문도 같은 방향으로
과대추정되고, CJK 는 반대입니다. 그러면:

```
fr    추정이 크다 → 실제로는 여유가 있는데 대화를 먼저 버린다
ja/zh 추정이 작다 → 실제로는 넘쳤는데 안 버린다 (8/23 에 20% 초과를 이미 한 번 잡았다)
```

**제안 P2.** 계수를 언어별로 나눕니다 (본문 계수와 스키마 계수 분리 + 스크립트별 보정).
주석은 「나누면 오히려 나빠진다」 고 적고 있는데, 그 실측은 **전체 중앙값** 기준이었습니다 —
지금 문제는 평균이 아니라 **언어 간 분산**입니다. 판단 기준이 달라졌으므로 다시 재야 합니다.
세계 규칙은 안 바뀝니다 (한계도 경고선도 그대로).

### U3. 신생아는 유언을 **받는 그해에 옮겨 적을 수 없다** ★★

이슈 ④ 의 「17/17 이 유언을 남겼는데 후손 0명이 옮겼다」 에 대한 답입니다.

```
신생아 상태   convo = []  ·  last_prompt_tokens = 0  ·  under_pressure = False
             → memory_open = False → 도구 목록에 memory_write 가 **없다**
```

(재현: `python tools/audit/recheck.py` 가 아니라 아래 세 줄)

```python
a = loop._newborn("Asla9","Asla","ja",0,set(),1,"natural",cfg,itertools.count(1),random.Random(1))
agent_loop.under_pressure(a, cfg)                       # False
tools_for(cfg, memory=False)                            # memory_write 없음
```

유언은 태어난 다음 해 첫 차례에 **들은 말**로 도착합니다. 그때 옮겨 적을 도구가 없습니다.
도구가 열리는 것은 대화가 경고선을 넘은 뒤이고, 신생아는 고정비를 빼면 1,700~2,800 토큰을
더 쌓아야 합니다 — 여러 해입니다.

그리고 **도구가 열리는 바로 그 호출에서** `compact_after_memory` 가 가장 오래된 블록부터
버립니다. 유언은 대화의 **맨 앞**에 있으므로, 처음으로 기억을 쓸 수 있게 된 그 한 번의
호출이 곧 유언이 사라지는 호출입니다. 그 호출에서 유언을 본문에 넣지 않으면 영영 없습니다.

U1·U2 와 겹치면 더 나빠집니다. 축출은 **추정**(8,192)으로, 압박은 **실측**(5,734)으로
판정하므로, 추정/실측 비가 1.43 을 넘는 에이전트는 **압박에 닿기 전에 축출이 먼저**
일어납니다 — 그 사람에게 유언은 도구가 열리기도 전에 사라집니다. 라틴 문자라 추정이
큰 fr(Miris) 이 정확히 그 자리입니다.

> 이것은 **의도된 감쇠가 아니라 두 규칙의 사고**입니다. 「기억은 자리가 좁아진 뒤에만」
> (8/21, 폭주 대책)과 「유언은 기억이 아니라 들은 말이다」 (8/22, 계보 채널)가 각각 옳은데
> 겹치는 자리를 아무도 안 봤습니다. 지금 상태에서 유언 채널은 **구조적으로 0** 입니다 —
> 후손이 게으른 것이 아닙니다.

**제안 P3.** 유언을 받은 해에는 `memory_write` 를 연다 (압박과 무관하게 그 한 해만).
폭주 대책의 근거(「압박 전 206번 호출」)는 **모든 해**에 열려 있던 것이 문제였지 한 해가
문제가 아니었습니다. 대안으로 「태어난 다음 해 첫 차례에만」 도 같은 효과입니다.

이것은 검색을 붙이는 것이 아닙니다. **옮겨 적을지 말지의 선택을 실제로 존재하게** 만드는
것이고, 그 선택이 3.3 이 관측하려던 바로 그것입니다.

### U4. 기억이 대화와 **같은 예산**을 놓고 다툰다

MemGPT 의 working context 는 고정 크기라 큐를 밀어낼 수 없습니다. 우리 메모는 상한이
없고 system 안에 있으므로, 길게 쓰면 `fixed_tokens` 가 커지고 **대화가 그만큼 더 축출됩니다.**
상한은 `max_tokens 2048` 하나뿐이라 한 번에 창의 **25%** 까지 쓸 수 있습니다.

「길게 적을수록 더 많이 잃는다」 는 그 자체로 흥미로운 규칙이지만, **우리가 고른 규칙이
아니라 상한을 안 둬서 생긴 것**입니다. 그리고 이 되먹임은 감쇠 측정을 오염시킵니다 —
많이 적은 세대가 더 많이 잃으므로, 감쇠율이 「무엇을 적었나」 가 아니라 「얼마나 적었나」 를
따라 움직입니다.

**제안 P5.** 메모에 **글자 수 상한**을 둡니다 (구조가 아니라 크기만 — 아래 ⑤ 참조).
메시지 상한이 이미 언어별로 있으므로 같은 자리에 같은 모양으로 놓을 수 있습니다.

### U5. 경고가 「무엇을 잃는가」 도 「쓰면 무엇을 더 잃는가」 도 말하지 않는다

경고문은 한 줄입니다 — 「기억이 한계에 가까워졌다 · 오래된 것부터 사라진다」. 거래의 가격
(쓰면 경고선까지 추가 축출)이 프롬프트에 없습니다. 값을 안 알려주고 거래를 시키는 것은
비용표 없이 행동을 시키는 것과 같은 종류의 결함입니다 (#38 C6 과 같은 부류).

**제안 P6.** 경고문에 사실 한 줄을 더합니다 — 「적어 두면 오래된 대화가 그만큼 더 사라진다」.
지시가 아니라 사실이고, 이미 일어나는 일입니다.

### U6. 압박 빈도가 **노브 조건에 따라 다를 수 있다** ★

`comm_intl_ai` 가 싸지면 메시지가 늘고, 메시지가 늘면 대화가 빨리 차고, 그러면 압박이
빨리 오고 `memory_write` 가 더 일찍 열립니다. **핵심 독립변수가 기억 접근성을 바꿉니다.**
그러면 조건 간 비교에 기억 채널이 섞여 들어옵니다.

> 확인 방법: 조건별 「압박 진입 나이 중앙값」·「압박 아래 에이전트-해 비율」·「memory_write
> 건수」 를 조건별 표에 한 줄 추가. 세계를 안 건드립니다. → 제안 P7.

이것은 #38 이 찾은 「노브가 예산 240 위에서 무력해진다」 와 방향이 반대라 특히 봐야 합니다 —
돈으로는 안 무는 노브가 **문맥으로는 물** 수 있습니다.

### U7. 우리는 「몇 번 썼나」 는 세는데 「무엇이 살아남았나」 를 안 잰다

지금 로그에 있는 것: `memory_len` · `pressured` · `evicted_blocks` · `compacted_blocks` ·
`memory_write` 본문 ([agent_loop.py:938](../core/agent_loop.py#L938)). 없는 것: **한 사실이
몇 번의 재기술을 거쳐 몇 대까지 살아남는가.** 그것이 이 설계 전체의 존재 이유인데 지표가
없습니다.

**제안 P4.** 사후 지표 하나 — `memory_write` 본문의 판본 열을 이어 붙여, 한 판본에서 다음
판본으로 살아남은 항목(숫자·이름·약속)의 비율을 세고, 유언 → 후손 메모 → 그 다음 판본으로
이어지는 계보 사슬을 만듭니다. **로그만 읽습니다 — 세계도 프롬프트도 안 건드립니다.**
`tools/score/` 에 붙습니다.

### U8. 축출 단위가 「턴 블록」 이라 **한 번에 얼마를 잃는지가 통제되지 않는다**

블록 = user 관측 하나 + 뒤따르는 assistant/tool 전부 ([agent_loop.py:654](../core/agent_loop.py#L654)).
한 해에 도구를 15번 부른 사람의 블록은 3번 부른 사람의 5배입니다. 같은 「한 블록」 이
사람마다 다른 양을 뜻하므로, 감쇠의 단위가 사람마다 다릅니다. MemGPT 는 토큰 수로
(창의 ~50%) 자릅니다. **어느 쪽이 옳은지 우리는 논의한 적이 없습니다.**

### U9. `memory_open` 이 **직전 콜**의 토큰으로 정해진다

[state.py:62](../core/state.py#L62) 의 주석이 이미 인정하고 있습니다 — 목록은 직전 콜
크기로 정해지는데 실행은 이번 콜을 봅니다. 경계에서 「비용표에는 있는데 부르면 거절」 이
나오지 않도록 `agent.memory_open` 한 값을 공유하게 해 뒀지만, **첫 진입이 한 콜 늦는**
성질은 남아 있습니다. MemGPT 는 경고를 프롬프트 조립 시점에 넣으므로 이 지연이 없습니다.

## 4. 못 하는 차이 — 하고 싶어도 안 되는 것

| # | 무엇 | 왜 이 실험에서는 불가능한가 |
|---|---|---|
| X1 | 축출 결정을 **실측 토큰**으로 하기 | 실측은 응답에 실려 오고 축출은 요청 **전에** 해야 한다. 구조적으로 한 콜 늦는다. 추정을 없앨 수 없다 (정확도만 올릴 수 있다 — U2) |
| X2 | 페이징·검색 도구 추가 | ① 관측을 파괴한다 (I1) ② 그전에 **모델이 못 한다.** 논문 자신이 GPT-3.5 급에서 함수 호출 부족으로 성능이 크게 떨어진다고 적었고, 우리 에이전트는 `qwen3.6-35b-a3b` 다. 도구를 늘리면 스키마가 커져 창을 더 먹는 것도 겹친다 (지금도 2,402 토큰 = 창의 29%) |
| X3 | 기억 설계 A/B | 기억은 **세계 규칙**이라 조건을 늘리면 런이 배로 든다. 남은 일정(8/30)에 Phase 2 격자(노브 4 × 시드)가 이미 잡혀 있고, 규칙을 바꾸면 기존 런과의 비교가 끊긴다 |
| X4 | MemGPT 벤치마크로 비교 | DMR·nested KV·문서 QA 는 전부 **정답이 있는 검색 과제**다. 우리 세계에는 물어보는 사용자도 정답 집합도 없다. 「기억을 잘하는가」 를 그 자로는 못 잰다 |
| X5 | 축출된 것이 결정을 어떻게 바꿨는지 | 반사실이다. 같은 시드에서 축출만 끄면 다른 세계가 되고(프롬프트가 달라지면 응답이 달라진다) 비교가 성립하지 않는다 |
| X6 | 재귀 요약을 우리 손으로 넣기 | 넣는 순간 「무엇을 남길지」 가 우리 모델의 선택이 된다. 에이전트의 선택을 재는 자리에 우리 선택을 심는 것이라 I2 와 정면으로 충돌한다 |

## 5. 이슈가 물은 다섯 가지 — 한 줄 답

**① 되돌릴 수 없다는 점.** 의도. 경계는 이미 「내가 적은 것은 남고 들은 말은 사라진다」 로
그어져 있습니다 (메모는 system 에 있어 축출 대상이 아님). 더 붙일 것은 에이전트 쪽이
아니라 **관측 쪽**입니다 → P4.

**② `memory_write` 를 압박 뒤로 숨긴 것.** **처방이 원인에 안 맞았습니다.** 8/21 폭주의
원인은 「도구가 늘 열려 있어서」 가 아니라 **경고가 안 꺼져서**였습니다. MemGPT 의 큐
매니저는 flush 로 큐를 실제로 줄이므로 경고가 스스로 꺼집니다 — 논문에 「도구를 숨긴다」 는
발상 자체가 없는 이유가 그것입니다. 우리는 8/22 에 `compact_after_memory` 로 **원인도**
고쳤습니다. 그러니 숨기기는 지금 중복이고, 부작용(U3 유언 채널 사망)이 남아 있습니다.
**전부 여는 것에는 반대합니다** — 압박 전 206회는 순차 라운드로빈에서 남의 차례를 먹는
실제 비용입니다. 좁게 여는 것이 맞습니다 → P3.

**③ 압축을 거래로 만든 것.** 옳습니다. 다만 파는 것은 「공간」 이 아니라 **「무엇이 남을지의
선택권」** 이고, 그 가격이 프롬프트에 안 적혀 있습니다 → P6.

**④ 계보를 타는 기억.** 후손 0명은 **구조적**입니다 (U3). 신생아는 압박이 없어 도구가 없고,
도구가 열리는 그 호출이 유언을 지우는 호출입니다.

**⑤ 구조 없는 단일 문자열.** **구조는 주면 안 되고 크기는 줘야 합니다.**

```
스키마를 주면 (persona/사실/약속 …)   무엇을 남길 가치가 있는지를 우리가 가르치는 것 →
                                      「무엇을 남기는가」 가 관측 대상인데 답을 준다
크기 상한을 주면                       무엇을 버릴지는 여전히 본인이 고르고, 감쇠율이
                                      「얼마나 적었나」 에 끌려다니지 않게 된다 (U4)
```

MemGPT 의 고정 크기 블록에서 **가져올 것은 「고정 크기」 이고 「블록」 이 아닙니다.**
